## 1. 项目概述

### 1.1 项目背景
为教堂/教室提供一个完整的显示系统，支持音乐播放、文章阅读导航、板书投屏等功能，通过单控模式实现设备集中管理。

### 1.2 项目目标
- 实现音乐播放与歌词同步显示
- 支持圣经文章**人工阅读与导航**
- 提供板书投屏功能
- 统一管理多个显示设备

### 1.3 技术架构选型
| 组件 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | Preact + TypeScript + Tailwind | 高效开发，包体积小 |
| 后端 | Cloudflare Workers | 全球分布式，成本低 |
| 数据库 | Cloudflare D1 (SQLite) | 不需要独立数据库 |
| 实时通信 | EMQX MQTT over WebSocket | 低延迟，保消息 |
| 存储 | Cloudflare R2 | 对象存储，成本低 |

## 2. 功能需求

### 2.1 音乐播放器
**用户故事**: 作为教师，我希望播放圣歌并显示歌词。

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 播放/暂停/继续 | 控制播放状态 | P0 |
| 进度条 | 支持拖动到任意位置 | P0 |
| 音量调节 | 0-100 可调 | P0 |
| 歌词同步 | LRC 格式歌词时间轴同步 | P0 |
| 播放列表 | 列表展示，选择即添加 | P0 |
| 专辑封面 | 显示音乐封面图片 | P1 |
| 伴奏切换 | 支持主音轨/伴奏切换 | P1 |
| **控制端全词** | 控制端显示**全部歌词**，随播放进度滚动，当前行变色（与投屏端进度一致） | P0 |
| **投屏一屏行数** | 投屏端大字**只显示当前一屏行数**（按屏高与字号算，不写死行数） | P0 |
| **进度条位置** | 进度条＋播放/上一首/下一首**贴内容区底部** | P0 |
| **选曲不上屏** | 点预选列表只切控制端；**点播放才上屏**（未播放前投屏保持待机背景） | P0 |
| **添加歌词** | 模态框：顶部搜索；左 **1/5** 歌曲本（首项「全部」）；右侧最近播放；`＋/－` 加入/移出；名称前缀如 `【新】001.我爱我的祖国` | P1 |
| **歌词字号（V1.3）** | 音乐**内容区顶部** `A− 24px A＋`（步长 2px，量程 20–48）；**一个控件同时决定控制端与投屏**，不做两套 | P0 |
| **投屏自适应（V1.3）** | 投屏字号按「屏宽×0.92 ÷ 最长行字数 × 档位系数」实算（32–140px），左右边距 4%，不再固定大边距 | P0 |
| **歌名卡（V1.3）** | 点播放后、**歌词第一行出现前**，投屏居中放大显示 `【新】001.我爱我的祖国`；歌词一开始即撤；字号≈歌词 1.2 倍 | P1 |
| **预选带书简称（V1.3）** | 「今日预选」每首**必须**带书本缩写：`【新】001.我爱我的祖国`（上一版只改了模态框，列表漏了） | P0 |

**数据源**:
- **分类接口**: `GET /ry-api/start/shijidb/list?pageNum=1&pageSize=100&isUpper=1`
- **音乐列表**: `GET /ry-api/start/zanmei/sgbList` (1223 首)
- **音乐详情**: `GET /ry-api/start/zanmei/sgb/{id}` (包含 LRC、音频、封面)

### 2.2 文章阅读导航器
**用户故事**: 作为教师，我希望浏览和查找圣经经节，人工阅读无需自动播放。

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 书卷列表 | 显示所有书卷 (如约伯记、诗篇等) | P0 |
| 章节导航 | 书 → 卷 → 章 → 节四级结构 | P0 |
| **经文浏览** | 点击章节查看经文内容（纯文本显示） | P0 |
| **浏览模式** | 人工阅读，无需播放控制 | P0 |
| **非播放任务** | 无自动播放、无速度调节 | P0 |
| **参数 ＋/−** | 每行（步长 1）、字号（2px）、行距（0.2）全部改为 ＋/− 控件，不用滑杆 | P0 |
| **按容量分页** | 投屏端按自身容量分页；控制端只负责**选节**，不传页码 | P0 |
| **选中节在第一行** | 投屏页的**第一行**必须是被选中那一节 | P0 |
| **发送本节** | 文章与音乐/板书一致：点「发送本节」才上屏 | P0 |
| **字号控件位置（V1.3）** | 「字号 A−/A＋」移到**文章内容区顶部**，与音乐区同位置、同一样式 | P0 |
| **从 m 节到 n 节（V1.3）** | 内容区顶部设 m、n（各配 ＋/− 且**可直接输入**）；默认 m=1、n=本章末节；投屏内容＝m→n，控制端正文随 m→n 变化 | P0 |
| **到第 n 节为止（V1.3）** | 取代「自动上滚到最后一节」：上滚只到第 n 节；m 节仍是投屏第一行 | P0 |
| **正文字号位置（V1.5）** | 「正文字号 A− 100% A＋」只在**文章内容区顶部**（页头不再有百分比控件，避免误以为会改音乐歌词/板书字号）；范围 80%–160%、步长 10%，**只改控制端阅读区** | P0 |
| **m→n 控件样式（V1.5）** | 「从 m 节 / 到 n 节」与「字号」同款 stepper（胶囊边框＋−/＋，可直接输入），不再用独立样式 | P1 |
| **卷列表对齐（V1.5）** | 66 卷一律**等宽格子**：单字「创」与双字「撒上」同宽，行列对齐、不出现滚动条（PC 6×11，移动 8×9） | P0 |
| **添加经文两栏（V1.3；V1.4 改简写）** | 左 1/3 搜索＋**66 卷简写流式**（创/撒上/林前…，一屏排完不滚动，悬停给全名与章数）；右 2/3 搜索＋章号网格（10 列）；点选/反选**实时**进预选，**取消「加入预选」按钮** | P0 |
| **经文检索（V1.4）** | 简写、全名、去缀短名、常见别名都能搜：输 `创世纪` 命中 `创世记`，输 `创` 也命中 | P0 |

**表结构**:
- **wenzhang_volumes** (卷表): id, name, pinyin, chapter_total, testament_sn
- **wenzhang_verses** (节表): id, volume_id, chapter_sn, verse_sn, verse_txt

## 3. 非功能需求

### 3.1 性能要求
| 指标 | 要求 | 说明 |
|------|------|------|
| 页面加载 | < 2 秒 | 首屏加载时间 |
| 控制延迟 | < 500ms | 从控制到设备响应 |
| 并发支持 | > 100 设备 | 同时在线设备数量 |
| 歌曲切换 | < 2 秒 | 从选择到播放完成 |

### 3.2 安全要求
- 所有 API 接口需要 JWT Token 认证
- 密码使用 bcrypt 哈希存储
- 敏感操作需要二次验证
- 设备码每 30 秒刷新一次

### 3.3 可靠性要求
- 99.9% 系统可用性
- 音乐播放失败时有降级方案
- 设备掉线自动重连机制
- 数据库每日自动备份

### 3.4 可维护性要求
- Docker 容器化部署
- 日志结构化记录
- 健康检查 API
- 错误告警机制

## 6. UI/UX 要求

### 6.1 设计原则
- **简洁优先**: 核心功能前置，减少点击次数
- **视觉引导**: 通过颜色/图标区分状态
- **操作确认**: 关键操作需要确认提示
- **响应迅速**: 所有反馈在 200ms 内
- **发送可见（V1.2）**: 三类内容一律「点了发送/播放才上屏」——点选只改控制端，投屏不动
- **状态可分（V1.2）**: 「在线（在册）」与「已连接（MQTT）」必须一眼可分，不能合成一个数

### 6.2 核心页面（V1.2 改写）

控制端一屏四场景，场景互斥，**待机为默认**：

1. **待机**：背景缩略图列表（第 1 项黑屏）＋ 编辑模式（增删）＋「保持宽高比/铺满」
2. **音乐**：内容区顶部字号 A−/A＋（两端联动）；全部歌词随进度滚动；底部进度条＋播放；预选选曲不上屏；点播放后、歌词出现前投屏居中显示歌名
3. **文章**：内容区顶部「字号 A−/A＋」＋「从 m 节到 n 节」；每行/行距 ＋/−；「发送本节」；投屏按容量分页、m 节在第一行、到 n 节为止
4. **板书**：编辑区＋「发送」；行数/字号/行距 ＋/−；未发送前投屏保持待机
5. **添加歌词**（模态框）：搜索＋歌曲本（1/5，首项「全部」）＋最近播放＋`＋/－`
6. **添加经文**（模态框）：左 1/3 搜索＋66 卷（**简写流式**），右 2/3 搜索＋章号网格（10 列）；点选/反选实时进预选，无确认按钮
7. **设备状态**：顶栏一处两段（在线 / 已连接），完整文案走 tooltip

> 不再单列「设备管理」页：设备只有只读状态，无选设备页（V2.0 起）。

### 6.3 交互细则
- **弹窗高度稳定（V1.6）**：添加曲目、添加经文两个弹窗，**切换歌本 / 切换书卷 / 输入搜索**时高度必须纹丝不动；内容多出来的部分在各自格子里滚动。任何一次高度变化都按缺陷记。
（V1.2，与原型 v1128 一致）

| 项 | 细则 |
|---|---|
| 上屏时机 | 音乐＝播放；文章＝发送本节；板书＝发送或双击。切 Tab 只切控制端 |
| 切换歌曲 | 正在播时再选曲：投屏停在原曲，控制端切新曲待播 |
| 预选列表 | PC 左侧可收缩＋右边框搜索；**移动端四模块＋「预选」合成底部操作栏**，预选浮层贴栏上沿升起；添加弹层再叠一层蒙版 |
| 页面底部 | 音乐进度条、文章控制条、板书发送条均**贴内容区底部** |
| 参数步长 | 文章：每行 1 / 字号 2px / 行距 0.2；板书：行数 1（默认 6）/ 字号 2px / 行距 0.2（默认 1） |
| 主题 | 白天奶白 / 夜间原色；黑屏恒纯黑、无文字 |
| 歌词字号（V1.3） | 音乐内容区顶部 A−/A＋（20–48，步长 2）；**一个控件定两端**；投屏按屏宽 0.92 实算后叠加档位（32–140） |
| 歌名卡（V1.3） | 播放后至歌词第一行前，投屏居中显示「书简称+编号+歌名」，字号≈歌词 1.2 倍，歌词到即撤 |
| 文章字号（V1.3） | 移到内容区顶部，与音乐同位置同样式 |
| 投屏范围（V1.3） | 从 m 节到 n 节：默认 1～末节，越界钳制；m 节仍是第一行，到 n 节为止 |
| 正文字号（V1.5） | 仅改控制端文章阅读区（80–160%、步长 10%）；投屏字号用「字号 A−/A＋」；音乐歌词与板书各有自己的控件 |
| 卷列表对齐（V1.5） | 等宽网格，单/双字同宽；检索仍支持全名/简写/短名/别名（`创世纪`→创世记） |
| 添加经文（V1.3；V1.4 简写） | 左 1/3 卷（**简写流式**，搜索支持简写/全名/别名）＋右 2/3 章（搜索、10 列网格）；选中/反选实时同步预选，无「加入预选」按钮 |
