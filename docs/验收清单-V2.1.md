- **用法**: 每条给"怎么点 / 期望什么"，打钩即通过；❌ 必须附截图或 msgId
- **时间口径**：版本号后括注的时间＝**该版主体提交（首笔）的 committer time**（UTC+8，精确到分，后附 sha，可直接复核）；同一版本后续的「补」提交**不改版本号、不重打时间**（否则自指不自洽）。**当版条目先只写 sha**，时刻由 sha 查得后补——**不得预算提交时刻**：本轮我就把 V2.1.51 写成 23:41（实为 23:37）、V2.1.52 写成 23:54（实为 23:44），两次都是「先写时间再推提交」。**正文里转述他人消息的时刻是近似值**（保留「xx:xx」或带 `x` 的写法），不作版本证据、也不用来判谁在先——判先后只认 sha。
- **实现存在性前置门（V2.1.55）**：本清单凡写成 `rg … src/…` 的判据，前置条件＝**生产源码已入库**。当前树只有 `docs/`、`prototype/` 与根级 md，**没有 `src/`** ⇒ 这类判据一律记「**未可执行**」，**不得记通过**。原因：`rg` 对不存在的路径 **exit 2、输出 0 行**，`| wc -l` 也是 0 ⇒「0 命中」恒真（实测 `rg -c '^- \[ \].*src/' ` = **32 条**；**V2.1.59 复测 33 条**——原 32 条＋本条总则自身，V2.1.57/58 的 32 是旧计数）。与「`cds.controlCode` 恒为 null ⇒『被清』恒真」（V2.1.54）同一形态：判据测的是「路径不存在」，不是「代码里没有」。 **【V2.1.59 计数与边界】**计数按 `rg` 算：含 `rg ` 的 `src/` 判据＝**33 条**（`rg -c '^- \[ \].*src/'` 现为 **33**＝原 32 条＋本条总则自身；V2.1.57 写的「32 条」、V2.1.58 一度出现的「34」都不对，34 的成因见下）。**V2.1.58 误标一条**：`触屏有固定发送按钮` **不含 `rg`**、今天就能在原型上验（390×844＋`isCoarse()`），原注「`src/` 前置门适用」是错的，已删——**V2.1.58 当时**按「含 `src/` 的条目」计数会得 **34**，那是把这条误标注记算了进去（修正后实测 **33**）。**否定式判据必须配主体存在性锚点**：凡「`rg … src/…` 0 命中」类判据，`src/` 入库后**不得只跑 0 命中就记通过**，须同时给一条主体存在性证据（例：`rg -c 'performance.now' src/display/player/` ≥ 1）。否则模块一行没写也会全绿——`src/` 一入库，33 条否定式判据会同时变绿。
