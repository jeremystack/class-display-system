## 2. 架构决策变更

| 决策 | V2.0 | V2.1 | 理由 |
|------|------|------|------|
| **D-A** 音频位置 | 音频在显示端（`<audio>` 只在 display） | **反转**：音频在**控制页**（console / 单屏页）；display 无音频 | ⑤；且一次性消掉全部浏览器自动播放风险（见 §3.1） |
| **D-C** 互斥仲裁 | 服务端仲裁三态 | 不变，但场景集合扩到四态；`standby` 也是场景，也走仲裁 | ③ |
| **D-D** 样式是数据 | 一套全局样式 | **按场景分域**：每场景一套 + 独立版本号 | ④ |
| **D-E** 控制码 | 一次性配对票据 | 不变。**新增：单屏模式不用控制码**（同账号同机，页面本身已鉴权，见 §5.3） | ⑥ |
| **新增 D-G** 音频锚点 | — | **音频锚点＝控制页**（哪一页在放，声音就从那台设备出）；同一 origin 同一时刻只允许一个锚点（lease） | ⑤ 的物理后果，§4.1 |
| **新增 D-H** 单屏模式 | — | 单屏模式是**第三种控制形态**：一台机器同时是控制端与显示端，页面在 console 域、用 JWT，**不是**把控件塞进 display.html | ⑥，§4.2 |
| **新增 D-I** 分页归属 | 控制台按"每屏几行"算 | **分页只在渲染端算**（display / 单屏页），`pageMap` 上报；控制台只发"下一屏"，**不持有页码** | ⑦，§4.4 |
| **弃用选项**（记录，不实现） | — | 若将来必须"手机控制 + 教室出声"，唯一出路是把 `<audio>` 搬回 display 并重开 autoplay 豁免（即 V2.0 的 D-A 旧案）。**本次不实现、不预留开关**，仅记录以便日后识别这是"回头路"而不是新需求 | §3.2 |

### 3.1 但 §10.6 不能全删空——留一条架构约束

删掉"怎么做 autoplay"是对的；**不能连"声音从哪出"也不写**，否则下一次有人看到"显示端放歌词没声音"会当 bug 处理。V2.1 §10.6 改为一段「音频锚点」，核心三条：

1. 声音只从**控制页所在设备**出；display 永不发声。
2. 控制页跑在哪台设备，就要求那台设备接了场地音响（笔记本线路输出 / 单屏模式的 HDMI 回传 / 蓝牙）。
3. 移动端控制页锁屏即静音（浏览器行为，不可绕过）→ 现场用手机控制时，音乐场景默认不可用。

### 3.2 §5.1 异议：这是我唯一真正担心的一条（请 Jeremyzh 确认）

⑤ 在"显控一体"下成立且最自然；在"手机控制 + 教室大屏"下**物理不成立**：

| 部署形态 | 控制页设备 | 教室声音从哪出 | ⑤ 是否成立 |
|----------|-----------|---------------|-----------|
| 显控一体（HDMI 复制，单屏模式） | 同一台电脑 | 该电脑 → 投影/外接音响 | ✅ 最自然 |
| 教师笔记本控制 + 扩展屏/第二台屏 | 笔记本 | 笔记本喇叭或线路输出 | ✅ 可用（音量与接线属现场事） |
| 手机控制 + 教室大屏 | 手机 | **手机喇叭** | ❌ 教室听不到 |
| 平板控制 + 教室大屏 | 平板 | 平板 | ❌ 同上 |

**结论**：音乐可用 ⟺ 控制页跑在接了场地音响的那台机器上。这不是实现细节，是**部署前提**，必须写进设计意图，且在控制台音乐面板常驻一行「声音将从本机输出」，避免老师以为投了没声音是故障。

**你要决定的是**：接受"音乐只在控制页=主机时可用"，还是要"手机也能控制教室出声"？
- 若接受 → 按 V2.1 走，手机端音乐面板显式置灰并说明原因（我的建议）；
- 若要后者 → ⑤ 不成立，`<audio>` 必须回 display，autoplay 章要整套恢复（含形态 B/C 判定）。**这条要 Jeremyzh 一句话**，我不替他拍。

## 4. 逐条详设

### 4.1 音乐：跨文档时基（⑤ 的实现核心）

control 页持 `<audio>`；display 只做"歌词跟随"，因此需要一条**不依赖消息频率**的时基：

```
player.play  { trackId, audioUrl, positionMs, durationMs, startedAtEpochMs }
              ↑ startedAtEpochMs 由服务端 ack 填写（不用客户端互发时间，避免两台设备时钟差）
```

- display：`pos = positionMs + (playing ? now - startedAtEpochMs : 0)`，`rAF` 推进高亮，**不逐行下发**（每秒多次消息会打爆单连接）。
- 校正：控制页每 5s `state.report`（既有通道）报一次真实 `positionMs`；**漂移 >200ms 才跳**，否则不打断。
- 暂停/续播：`playing:false` 冻结高亮行；`resume` 带新 `positionMs + startedAtEpochMs`。
- **同一 origin 只允许一个音频锚点**（防双窗回声、防 console 与 `#/screen` 同时解码）：
  - `localStorage.cds.audio.lease = { owner, ts }`，owner 每 2s 心跳，3s 未续视为过期；
  - 抢不到的一侧**静音跟随**，控制条显示「另一窗口正在播放，此处静音」；
  - 这一条不做，现场症状是"投了有回声/两轨错位"，极难查。
- 移动端：`visibilitychange → hidden` 即 `pause` 并记位置；回前台**不自动续播**（防止教室突然出声），提示「已暂停，点播放继续」。

### 4.2 单屏模式（⑥）：新页面，不是新控件

**结论：同意 Chief —— 控件绝不进 `display.html`。** 理由补两条：display 只持设备级凭据（无控制权），加控件＝提权；且会出现"设备凭据 / 用户 JWT"两套鉴权分支，安全评审必挂。

| 项 | 设计 |
|----|------|
| 路由 | `/#/screen`（console 域，JWT 鉴权，需登录） |
| 布局 | 全屏渲染面（与 display 同一套 scene 组件）+ 底部**迷你控制条**（≤6 个控件） |
| 迷你控制条 | `待机 · 音乐 · 文章 · 板书`｜`⏮ ⏯ ⏭`（音乐）｜`上一屏 · 下一屏`（文章）｜`黑屏`｜`退出单屏` |
| 鉴权 | **不需要控制码**（同账号同机）。需 `POST /session/single` 用 JWT 换一条本机设备凭据，供 `state.report` / 心跳使用（§6-1） |
| 与多屏共存 | 同一账号可同时开单屏页 + 教室屏；两处渲染同一 `scene`；**音频只在单屏页**（它是控制页） |
| 隐藏 | 控制条 3s 无操作淡出至 12% 透明度，鼠标移至底边 80px 唤回；键盘 `Esc` 唤回；不设常驻按钮 |
| 退出 | 退出即回 `#/console`，**不**自动解绑设备凭据（下次进来直接用） |

**渲染器复用**：`src/display/scenes/*` 提升为 `src/shared/render/*`，由 display 与 `#/screen` 共用。禁止复制一份——否则"投影上排出来和预览不一样"，分页也会算错。

### 4.3 §5.2 异议：复制模式下控制条**学生会看到**（这条必须在文档里说破）

- 显控一体 = **HDMI 复制**（镜像）→ 投影上是老师屏幕的逐像素副本，**包括迷你控制条、包括你点"黑屏"的那一次点击**。
- 因此：
  1. 「黑屏」的真实作用是**不让学生看到下一条内容**（老师在本机准备下一篇经文时先黑屏），**不是防窥**；不能承诺"学生看不出老师在操作"。
  2. 控制条必须做**小 + 淡出**，且默认半透明 12%（宁可老师自己看不清，也别在大屏上刺眼）。
  3. 若老师确实需要"学生看不到我的操作"→ 只能**扩展模式 + 手机控制**（= 多屏模式），而那条路又回到 §3.2 的音频矩阵（手机不出声）。这两个诉求在物理上互斥，选一个。
- 设计意图段（V2.1 §9.0）必须原样写下这三句，避免现场以"我以为学生看不到"翻车。

### 4.4 文章：两步投屏（②）+ 分页实测（⑦）

**② 两步，我同意 Chief 的不对称，但理由要写对**：音乐"点即播"是因为上行内容是**曲名自动跟随**、一步可撤（点暂停）；文章的屏上内容是**滚动位置**，需要"定稿再上屏"，所以两步。不对称不是妥协，是两个内容物的性质不同。

```
article: idle → preview(在本机挑/翻) → presenting(已上屏) → idle(结束投屏→回 standby)
```

- 「开始投屏」= 把**当前这一屏**（含当前样式）原子下发；「结束投屏」= 回 `standby`（不是"等待控制台"，因为待机已有主题/黑屏两个形态）。
- 结束投屏**保留阅读位置**；再次投出从原位置继续。
- 单屏模式下这两个按钮进迷你控制条（`上一屏/下一屏` + `投出/结束`）。

**⑦ 分页（我的实现口径）**

| 项 | 规则 |
|----|------|
| 谁来算 | **渲染端**（display / 单屏页）。控制台的预览窗与投影物理尺寸不同，算不准也不该算 |
| 何时算 | `await document.fonts.ready` → `requestIdleCallback` 测量；**字体加载 3s 超时按 fallback 度量**（否则弱网永久白屏） |
| 怎么算 | 以「节 + 字符偏移」为原子，二分法找每页能容纳的最大偏移；产出 `pageMap = [{start:{verseSn,charOffset}, end:{...}, cont:bool}]` |
| 变化即重排 | `ResizeObserver`（200ms debounce）+ 字号/字体/行高变更 → 重排 → **重发 pageMap** |
| 状态锚点 | **状态是 `anchor`，不是页码**：`{volumeId, chapterSn, verseSn, charOffset}`。重排后按 anchor 重新定位到"包含 anchor 的那一屏"，页码只用于显示「3/12」 |
| 「续」标记 | 放**页脚小字**（`::after` 或独立元素），**不得插入经文正文**——否则复制/朗读/校对会带脏字符，宗教场景尤其不能动原文 |
| 禁止 | 显示端滚动（大屏无人操作）；`overflow:auto`；按字数/行数估算 |
| 上报 | `state.report.pageMap` 只报摘要 `{anchor, pageIndex, pageCount}`，**不回传整张表**（表可能几十 KB，5s 一条不可接受） |
| 落库 | **不落库**（§7） |

## 5. 其余三条需求的确认

| 需求 | 我的处置 |
|------|---------|
| ③ 待机主题 | 同意四态。`standby` 两形态：`theme`（内置主题图，`cover` + 压暗层）与 `blank`（纯黑）。**P0 只做内置 6 张 + 纯黑**；自定义上传（R2 预签名、≤1920×1080/≤1.5MB、剥 EXIF）单列 P1——上传涉及审核/存储/清理，塞进 11-25 MVP 会挤掉主链路 |
| ④ 样式分域 | 同意。`display.style {scene, styleVersion, …}`，每场景独立版本；切场景**先套该场景缓存再渲染**（`localStorage.cds.style[scene]`），这是"原子下发"的真含义：不是同时发，而是"不出现一帧默认样式" |
| ⑥ 迷你控制条 | 见 §4.2；另补一条防误触：预选清单条目**必须 `pointerup` + 8px 位移阈值**才触发"点即播"，否则老师上下拖排序时会把音乐放到教室 |
| ⑦ PPT 并存 | **物理约束必须写进设计意图**（Chief 第 7 条）：复制模式下无法同时显示 PPT 或其他软件。三条现场出路：① 把 PPT 导出 PDF 走板书场景（推荐）；② PPT 窗口化（学生仍看到整个桌面，效果差）；③ 换扩展模式 + 手机控制（音频按 §3.2 降级）。**不要对外承诺"能一边放 PPT 一边控制"** |

## 6. 需要开发/运维定的接口（我不改 api.md / mqtt.md，仅给需求与语义）

| # | 需要 | 现有为什么不够 | 影响 |

| 4 | `article.present` / `article.end` | `article.navigate` 是"定位"，不是"上屏"；② 需要显式生命周期，且 `end` 要回 `standby` | ② |
| 5 | `article.scroll` 语义改 `{direction:'next'\|'prev', steps:1}` | 现在按 `lines`（行数）下发，而分页由渲染端实测，行数没有意义 | ⑦ |

| 8 | `presence` 增 `mode:'single'\|'display'` | 终端计数要能区分"单屏页"和"教室屏"，否则老师看不懂"1 个终端在线"是谁 | ⑥ |

## 7. 0005 零成本窗口：我的结论（这是最后一次机会，请开发照此定）

| 数据 | 落库？ | 理由 | 最小结构 |

若开发不愿在 0005 加表：P0 兜底 = `localStorage` + 每次连上全量重推，代价是**新设备首次连上必有一帧默认样式**（闪一下宋体/白底）。我建议加，因为这张表只有 5 列，且样式是高频改动项。
