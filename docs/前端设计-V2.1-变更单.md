### 3.1 但 §10.6 不能全删空——留一条架构约束

删掉"怎么做 autoplay"是对的；**不能连"声音从哪出"也不写**，否则下一次有人看到"显示端放歌词没声音"会当 bug 处理。V2.1 §10.6 改为一段「音频锚点」，核心三条：

1. 声音只从**控制页所在设备**出；display 永不发声。
2. 控制页跑在哪台设备，就要求那台设备接了场地音响（笔记本线路输出 / 单屏模式的 HDMI 回传 / 蓝牙）。
3. 移动端控制页锁屏即静音（浏览器行为，不可绕过）→ 现场用手机控制时，音乐场景默认不可用。

### 3.2 §5.1 异议：这是我唯一真正担心的一条（请 Jeremyzh 确认）

⑤ 在"显控一体"下成立且最自然；在"手机控制 + 教室大屏"下**物理不成立**：

| 部署形态 | 控制页设备 | 教室声音从哪出 | ⑤ 是否成立 |
|----------|-----------|---------------|-----------|
| 显控一体（HDMI 复制，单屏模式） | 同一台电脑 | 该电脑 → 投影/外接音响 | ✅ 最自然 |

## 4. 逐条详设

### 4.1 音乐：跨文档时基（⑤ 的实现核心）

control 页持 `<audio>`；display 只做"歌词跟随"，因此需要一条**不依赖消息频率**的时基：

```
player.play  { trackId, audioUrl, positionMs, durationMs }
              ↑ 不带任何时间戳（V2.1.1 删除 startedAtEpochMs，理由见下）
```

- display：`t0 = performance.now(); base = positionMs + delayMs; pos(t) = base + (performance.now() - t0)`，`rAF` 推进高亮，**不逐行下发**（每秒多次消息会打爆单连接）。
- `delayMs` 由控制页单侧测：发 `play` 记 `sendT`、收 `ack` 记 `recvT`，单程 `= (recvT - sendT) / 2`；取**最近 3 次的中位数**并 clamp ≤300ms，首播无样本取 0（V2.1.3：单次采样在教室 Wi-Fi 抖一下就能把歌词推后约 1s）。
- **为什么删掉 `startedAtEpochMs`（V2.1.1）**：服务端打点只消掉「控制台↔服务端」钟差，**消不掉「显示端↔服务端」钟差**。`positionMs + (Date.now() - startedAtEpochMs)` 用的是显示端的钟，而 D-1 的电视棒/盒子没有 NTP，钟可差几十秒到几分钟并随校时跳变 → 歌词整段跳或一路爬。开发机同机同钟，这个错**在本地永远测不出来**。残余误差只剩「服务端→显示端」单程延迟（一次性、10–100ms），不累积，靠 5s 重锚吸收。
- 页面重载后 `performance.now()` 归零，**不得续用旧 `t0`**：必须先 `GET /devices/{id}/state` 取当前 `positionMs` 再重锚。
- 校正：**下行 `player.sync`** 每 5s 一条（音频宿主＝控制页发、服务端转发），带 `positionMs/durationMs`；display 收到算 `Δ = (positionMs + delayMs) − pos(now)`，按**三档死区**处理（V2.1.7 修正方向：原句写「`state.report` 报一次」是错的——`state.report` 是 display→服务端**上行**，display 收不到自己的 report，拿它纠漂 `Δ` 恒为 0。V2.1.3）：`|Δ| < 80ms` 忽略；`80–300ms` 慢追（每帧靠 10%、单帧 ≤5ms）；`|Δ| > 300ms` 直接跳。口径以正文 §10.6 第 3 条为唯一来源，200ms / 250ms 两种旧写法作废。
- 暂停/续播：`playing:false` 冻结高亮行；`resume` 带新的 `positionMs`（不带时间戳），display 收到即重锚。
- **同一 origin 只允许一个音频锚点**（防双窗回声、防 console 与 `#/screen` 同时解码）：
  - `localStorage.cds.audio.lease = { owner, ts }`，owner 每 2s 心跳，3s 未续视为过期；
  - 抢不到的一侧**静音跟随**，控制条显示「另一窗口正在播放，此处静音」；
  - 这一条不做，现场症状是"投了有回声/两轨错位"，极难查。
- 移动端：`visibilitychange → hidden` 即 `pause` 并记位置；回前台**不自动续播**（防止教室突然出声），提示「已暂停，点播放继续」。

### 4.2 单屏模式（⑥）：新页面，不是新控件

**结论：同意 Chief —— 控件绝不进 `display.html`。** 理由补两条：display 只持设备级凭据（无控制权），加控件＝提权；且会出现"设备凭据 / 用户 JWT"两套鉴权分支，安全评审必挂。

| 项 | 设计 |
|----|------|
| 路由 | `/#/screen`（console 域，JWT 鉴权，需登录） |
| 布局 | 全屏渲染面（与 display 同一套 scene 组件）+ 底部**迷你控制条**（≤6 个控件） |
| 迷你控制条 | `待机 · 音乐 · 文章 · 板书`｜`⏮ ⏯ ⏭`（音乐）｜`上一屏 · 下一屏`（文章）｜`黑屏`｜`退出单屏` |
| 鉴权 | **不需要控制码**（同账号同机）。需 `POST /session/single` 用 JWT 换一条本机设备凭据，供 `state.report` / 心跳使用（§6-1） |
| 与多屏共存 | 同一账号可同时开单屏页 + 教室屏；两处渲染同一 `scene`；**音频只在单屏页**（它是控制页） |
| 隐藏 | 控制条 3s 无操作淡出至 12% 透明度，鼠标移至底边 80px 唤回；键盘 `Esc` 唤回；不设常驻按钮 |
| 退出 | 退出即回 `#/console`，**不**自动解绑设备凭据（下次进来直接用） |

**渲染器复用**：`src/display/scenes/*` 提升为 `src/shared/render/*`，由 display 与 `#/screen` 共用。禁止复制一份——否则"投影上排出来和预览不一样"，分页也会算错。

### 4.3 §5.2 异议：复制模式下控制条**学生会看到**（这条必须在文档里说破）

- 显控一体 = **HDMI 复制**（镜像）→ 投影上是老师屏幕的逐像素副本，**包括迷你控制条、包括你点"黑屏"的那一次点击**。
- 因此：
  1. 「黑屏」的真实作用是**不让学生看到下一条内容**（老师在本机准备下一篇经文时先黑屏），**不是防窥**；不能承诺"学生看不出老师在操作"。
  2. 控制条必须做**小 + 淡出**，且默认半透明 12%（宁可老师自己看不清，也别在大屏上刺眼）。
  3. 若老师确实需要"学生看不到我的操作"→ 只能**扩展模式 + 手机控制**（= 多屏模式），而那条路又回到 §3.2 的音频矩阵（手机不出声）。这两个诉求在物理上互斥，选一个。
- 设计意图段（V2.1 §9.0）必须原样写下这三句，避免现场以"我以为学生看不到"翻车。

### 4.4 文章：两步投屏（②）+ 分页实测（⑦）

**② 两步，我同意 Chief 的不对称，但理由要写对**：音乐"点即播"是因为上行内容是**曲名自动跟随**、一步可撤（点暂停）；文章的屏上内容是**滚动位置**，需要"定稿再上屏"，所以两步。不对称不是妥协，是两个内容物的性质不同。

```
article: idle → preview(在本机挑/翻) → presenting(已上屏) → idle(结束投屏→回 standby)
```

- 「开始投屏」= 把**当前这一屏**（含当前样式）原子下发；「结束投屏」= 回 `standby`（不是"等待控制台"，因为待机已有主题/黑屏两个形态）。
- 结束投屏**保留阅读位置**；再次投出从原位置继续。
- 单屏模式下这两个按钮进迷你控制条（`上一屏/下一屏` + `投出/结束`）。

**⑦ 分页（我的实现口径）**

| 项 | 规则 |
|----|------|
| 谁来算 | **渲染端**（display / 单屏页）。控制台的预览窗与投影物理尺寸不同，算不准也不该算 |
| 何时算 | `await document.fonts.ready` → `requestIdleCallback` 测量；**字体加载 3s 超时按 fallback 度量**（否则弱网永久白屏） |
| 怎么算 | ~~以「节 + 字符偏移」为原子，二分法找每页能容纳的最大偏移；产出 `pageMap = [{start:{verseSn,charOffset}, …}]`~~ **V2.1.6 作废**：改为**整章渲染行流 + 几何实测**（`lineY[]` / `verseLineIndex[]` / 页起点逐页递推 `pageStarts[]`），见 §4.8、§4.9 与正文 §7.5.1 |
| 变化即重排 | `ResizeObserver`（200ms debounce）+ 字号/字体/行高变更 → 重排 → **重发 pageMap** |
| 状态锚点 | **状态是 `anchor`，不是页码**：`{volumeId, chapterSn, verseSn, charOffset}`。重排后按 anchor 重新定位到"包含 anchor 的那一屏"，页码只用于显示「3/12」 |
| 「续」标记 | 放**页脚小字**（`::after` 或独立元素），**不得插入经文正文**——否则复制/朗读/校对会带脏字符，宗教场景尤其不能动原文。**V2.1.6 限定：只在 `unit=page` 出现**；`unit=section` 每屏都从节首开始，不需要「续」 |
| 禁止 | 显示端滚动（大屏无人操作）；`overflow:auto`；按字数/行数估算 |

### 4.8 V2.1.6：`unit=section` ＝视口按节步进（Jeremyzh 11:47 例子定死语义）

Jeremyzh 给的例子（诗篇 23，7 节，每节折行后 2 行，视口 5 行）：

- 第 1 屏＝节 1 两行 + 节 2 两行 + 节 3 第 1 行
- 点「下一节」→ 节 2 两行 + 节 3 两行 + 节 4 第 1 行
- 再点 → 节 3 两行 + 节 4 两行 + 节 5 第 1 行

**结论：`section` 不是分页、不是章内分屏，是「视口按节步进」。** 屏高不变、起点对齐节首、底部允许露出半节、相邻屏必然重叠（本例 3 行）——**重叠是预期，不是 bug**。这句必须同时出现在文档与验收里，否则会被当缺陷报上来。

| 项 | 怎么办 |
|----|--------|
| 算法 | 整章渲染为连续行流 → 铺出 `lineY[]`（每行真实 y）与 `verseLineIndex[]` → **页起点逐页递推** `pageStarts[]`（首个溢出 `H` 的行即下一页起点，段距自动计入）；`page` 走 `startLine = pageStarts[pageIndex]`，`section` 走 `startLine = verseLineIndex[sectionIndex]`；`translateY(-lineY[startLine])`。~~`N = floor(可用高/行高)` 当页容量~~ V2.1.7 作废入 |
| 定位 | 不切片文本：整章 DOM 常驻，外层 `overflow:hidden`，内层 `translateY(-startLine × 行高)` |
| 屏数 | 按 `unit` **现算、不预存**；`section` 模式屏数＝节数，UI 显示「节 3/7」 |
| 越界 | 末节不足 N 行 → 显示到章末、留空、**不回退起点**；`next` 到末节停住、提示「已到章末」、不跨章 |
| 「续」 | **只在 `unit=page`**；`section` 不需要，也不得因为「看起来接不上」补一个 |
| 「整章一屏」 | `sectionCount>1` 时出现；点击＝按步长 4 降 `fontSizePx` 到 1 屏；默认不动字号 |
| 文案 | 「节」＝**经节 `verseSn`** → 按钮写「**上一节/下一节**」（V2.1.7 纠正 V2.1.6 的「节＝章」；跨章仍走 `article.navigate`） |

**原型裁行 bug（这一条是我写出来的，根因在测量方式）**：V2.1.5 的 `measurePages()` 建了一个**平行 ruler**，ruler 里的 `<p>` 写 `margin:0 0 .9em`、正文 CSS 写 `1.1em`，而 `getBoundingClientRect().height` **不含 margin**——累加里根本没有段距。后果是**默认 72px 下就裁行**：3 个两行节测得 756≤911 通过，实渲染 756+3×79.2＝993.6 → `.body{overflow:hidden}` 静默裁掉最后一行；7 个单行节测得 882、实渲染 1436。改法：**不要平行测量层**，整章先渲染、读每节 `offsetTop/offsetHeight`，按真实几何切页与定位节首。两份段距 CSS 也就不存在漂移。

**板书字号（Chief 第六条）**：`display.html` 原 `.cast .paper{font-size:min(calc(var(--cds-font-size)*.9), 6.5vh)}`——6.5vh 在 1080p＝70.2px，**字号 72px 以上对板书全部无效**，与「远处看清」直接冲突。改为同一 `fontSizePx` + 装不下按**步长 4** 自动降档 + **控制页显示实际生效值**；不做静默缩。与「整章一屏」同逻辑：**降字号必须被老师看见**。

**物理约束（写进正文 §5.2，给老师看）**：可用高 ≈911px，行高 = `fontSizePx×1.75` ⇒ 72px→5 行、96px→4 行、120px→2 行。**「上限 120px」与「一屏 5–6 行」不能同时满足**，这是算术。UI 要显式标出「约 N 行/屏」，别让老师在课上发现。
### 4.9 V2.1.7：纠漂源、`pageMap` 分母、「节」的定义、行数更正

> 起因：开发 12:0x 提三问（经 Chief 转达）。三条中有两条是**我们会照着写出错东西**的旧口径，一条是数字错。另两条是我自查出来的。

**① 纠漂源方向反了（最严重，协议缺口）**

正文原写「每 5s 收到 `state.report.positionMs` 时算 `Δ`」。`state.report` 是 **display → 服务端的上行**，display 收不到自己的 report；即便自订阅也是拿自己刚发的值重锚，`Δ` 恒为 0、零纠偏，还会把上报延迟当漂移。

定稿：**新增下行 `player.sync {positionMs, durationMs}`**，由**音频宿主（控制页）每 5s 发**、服务端转发给 display；display 收到算 `Δ = (positionMs + delayMs) − pos(now)`，再走 80/300ms 三档。

- 为什么必须由音频宿主发：音频在控制页，只有它有真实 `currentTime`；服务端无音频，display 无 `<audio>`（V2.1 前提）。
- `mqtt.md` 目前**零命中** `player.sync` → **需开发补协议条目**（下行 topic、5s 周期、retain 不带此值）。这是 V2.1 的唯一新增下行消息。
- 反向检查（可 grep）：`src/display/player/**` 里 `state.report` **不得**出现在 Δ 计算路径上。

**② `pageCount` / `sectionCount` 的分母定死**

两个数**都恒报、与当前 `unit` 无关**：`pageCount`＝整章按 `page` 视口的屏数，`sectionCount`＝整章节数。`unit` 只决定**步进方式**与**显示哪一个**（`page` 显示「3/12」、`section` 显示「节 3/6」）。切 `unit` 不重发、页码不跳数，与 D-I「页码只用于显示」一致。

- V2.1.6 的「`pageCount` 按当前 unit 现算」**作废**。
- **不**采用「每屏带 `{startVerseSn, endVerseSn, contStart}`」的方案：那是整张表，5s 全量重传会打爆单连接，且改字号即过期。
- 另报 `viewLines`（当前一屏实测行数），供控制台旁注。

**③ 「节」＝经节（`verseSn`），不是章**

Jeremyzh 11:47 的例子是**一章之内**点「下一节」：诗篇 23 里 节1→节2→节3。V2.1.6 我按「节＝章」写，等于把一章之内的步进取消掉，与他给的语义直接冲突。改：`sectionIndex ± 1` 对应相邻**经节首行**；按钮文案「上一节/下一节」；跨章仍走 `article.navigate`（`chapterSn` 变）。

**④ 一屏行数更正（120px）**

| `fontSizePx` | 行高 | 一屏可行数（节首起算、允许底部露出半节） |
|---|---|---|
| 72（默认） | 126px | **5 行** |
| 96 | 168px | **4 行** |
| 120（上限） | 210px | **3 行**（节1 两行 552 + 节2 首行 210 = 762 ≤ 911；再一行 972 超） |

V2.1.6 写「120px→2 行」漏了「允许露出半节」这条自己定的规则，算错一档。另：旁注数字**不得**由控制台按 `floor(972/(px×行高))` 自算（972≠`clientHeight`≈911，且不含段距），一律取 display 上报的 `viewLines`。

**⑥ 页容量不能是 `N = floor(可用高/行高)`（开发实测 + 原型都撞了）**

每节自带段距（约 0.63 行），真实容量永远小于纯行数：1080p、72px 时公式给 7 行、真实 5 行。按 `pageIndex×N` 定位，页边界会落在行中间 → `overflow:hidden` 下表现为「最后一行被切掉」且不标「续」，最坏情况下每屏都少一行、要翻到第 8 屏才看完整章。

定稿：**页起点逐页递推**。`pageStarts[0]=0`；`pageStarts[k+1]` = 第一个满足 `lineY[j] + 行高 > lineY[pageStarts[k]] + H` 的 *j*；`pageCount = pageStarts.length`；`viewLines` = 首页行数（实测，供旁注）。定位用 `translateY(-lineY[startLine])`，**不做行号×行高换算**（换算会引入 ±半行舍入误差，72px 下 63px 足够把节首顶掉半行）。

原型 `display.html` / `screen.html` 已按此重写（V2.1.7），实测：72px、1280×800 窗口下诗篇 23 为 5 屏、每屏 4 行、无横切、页脚「（续）」正确。

**⑦ 顺带修**：「整章一屏」的出现条件由 `sectionCount>1` 改为 `pageCount>1`（它管的是「这一章需要几屏」，与节数无关）。

**零 schema 变更**；对显示端有新代码路径两处：收 `player.sync` 并按三档重锚、页容量改逐页递推。其余是文档口径。
