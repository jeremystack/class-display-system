> ### 口径红线（开发不得自行加回）
> 1. 文章模块是**人工阅读导航器**，不是播放器：**没有**朗读 / 语速 / 音量 / 自动播放，`article.*` 与 `/articles/*` 里不出现 `play`、`pause`、`speed`、`volume`、`autoPlay`。
> 2. 音乐播放只有 `player.*` 一套控制。
> 3. **画面互斥；"看内容"的画面下不得有声**（V2.1.2 定稿，依据 Jeremyzh「板书时不要放配乐」）：同一时刻 display 只渲染**一个**画面场景（`standby`/`music`/`article`/`cast`）。D-04 的"同一个 display 上图层并存"**永久废弃**（图层栈只有内容层 + 系统层，V2.0 的 L0–L3、`fullScreen`、`MiniPlayerBar` 都不回来）。音乐仍是**独立音轨**（声音在控制页，display 不知道音乐在播），但**`article` / `cast` 下不得为 `playing`**：进入这两态时由控制服务**先 `player.pause`、收到回执再切画面**；`cast.end` / `article.clear` 回 `standby` **不自动续播**；`standby` 允许背景音乐。V2.1.1 曾写"`article`/`cast`/`standby` 都允许背景音乐"，已作废。详见变更单 §4.5。
> 4. **控制在控制台，显示端只执行**：显示端除首次输码外，没有任何交互控件。
> 5. **控制码由控制台生成**，显示端输入。禁止再出现"显示端出码、控制台输码"的实现。
> 6. **音频锚点＝控制页**（V2.1）。`<audio>` 只存在于控制页（console / `#/screen`）；**display 里不得出现 `Audio` / `<audio>` / `AudioContext`**（`rg -i 'audio' src/display/` 只允许 `?debug=1` 的调试字段）。声音从哪台设备出＝控制页跑在哪台设备。
> 7. **待机是场景，不是空白**（V2.1）。`scene ∈ {standby, music, article, cast}`，`standby` 是默认态，有两个形态：主题图 `theme` / 纯黑 `blank`。任何"结束"动作都落回 `standby`，不落回"等待控制台"。

## 1. 两套界面，两个入口

| 端 | 使用者 | 形态 | 入口 | 职责 |
|----|--------|------|------|------|
| **控制台 console** | 教师 | 手机 / 平板 / 桌面浏览器 | `/#/login` → `/#/console` | 出控制码、挑今日内容、切三个场景、下发样式；**一屏搞定** |
| **显示端 display** | 无人 | 教室大屏 1080p | `/#/`（输码态）→ 内容态 | 输一次码，然后**纯执行**：渲染内容、套样式；**无 audio 元素、永不发声**（V2.1） |

**两条架构决策（继承 V1.0，仍有效）：**

- **D-A′ 音频在控制页播放（V2.1 反转，原 D-A 作废）。** `<audio>` 只存在于**控制页**（`/#/console` 或单屏模式 `/#/screen`）；display 只渲染歌词，**不解码、不加载音频**。
  - 推论 1：控制页进度来自本地 `audio.currentTime`（不再需要 5s 回执插值），拖动即 `seek` 本地。
  - 推论 2：display 的歌词高亮改由**本地单调时基插值**驱动（`pos = base + performance.now() - t0`，`t0` 在收到 `play` 时取，见 §10.6 第 3 条），不再有音频时钟，**也不使用任何 epoch 时间戳**（display 的墙钟不可信，见 V2.1.1）。
  - 推论 3：**声音只从控制页那台设备出**。这条是部署前提，不是实现细节：老师用手机控制时，教室听不到（详见 V2.1 变更单 §3.2）。
  - **前置条件**：音乐场景可用 ⟺ 控制页跑在接了场地音响的那台机器（单屏模式的电脑 / 接了线路输出的笔记本）。手机/平板控制页的音乐面板默认置灰并说明原因（**临时口径**：变体 2「手机当遥控器、电脑出声」一旦立项，置灰改为「能发指令、音频宿主不在此」，见 §14-9）。
- **D-B 控制台不乐观猜状态。** 任何控制指令等 `ack` 或 `state.report` 才更新权威状态；`ack` 3s 超时才提示。

**V2.0 新增架构决策：**

- **D-C 互斥由服务端仲裁（只管画面）。** 前端只发"我要切到某画面场景"，由服务端保证"旧**画面**先停、新画面再起"，`state.report.scene` 是唯一真相。前端**不做**本地抢先切换（允许 180ms 视觉过渡，但状态以回执为准）。**仲裁器不碰音轨，但"看内容的画面"必须无声**（V2.1.2）：`scene` 与 `audio` 是两个字段，仲裁器**不得**因切画面把 `audio` 置 `none`（要保留曲目与 `positionMs`）；进入 `article`/`cast` 的静音是**编排层显式发的 `player.pause`**（先 pause、收到回执再切画面），不是仲裁器隐式改音频、也不是显示端推断。
- **D-D 样式是数据，不是代码。** 显示端的字体/字号/行高/颜色/背景全部来自 `display.style` 下发的值，写进 CSS 变量；显示端不硬编码任何主题。
- **D-E 控制码是「一次性配对票据」。** 控制码由控制台生成，绑定成功即作废；刷新即作废旧码。多台终端 = 多张票据（为下一台屏幕再刷一个新码），已绑终端不受影响。终端集合在控制台侧是**计数**，不是列表。
- **D-F 码必须可枚举防御。** TTL 15 分钟 + 单次消费 + 边缘按 IP 限流 10 次/分钟（不能按码限流：攻击者猜的是不存在的码，没有行可累加）。

**V2.1 新增架构决策：**

- **D-G 音频锚点唯一。** 同一 origin 同一时刻只允许一个音频锚点（`localStorage.cds.audio.lease` + 2s 心跳，3s 未续作废）。抢不到的一侧静音跟随并在控制条标注。防的是"console 与 `#/screen` 同时开着导致双声/回声"。
- **D-H 单屏模式是第三种控制形态，不是显示端加控件。** `/#/screen`（console 域、JWT）＝全屏渲染面 + 迷你控制条；`display.html` 保持纯被动、零控件、只持设备凭据。两者**复用同一个渲染器**（`src/shared/render/*`），鉴权不分叉、不复制渲染代码。
- **D-I 分页只在渲染端算。** 分页结果 `pageMap` 由 display / 单屏页实测产出；控制台只发"下一屏/上一屏"，**不持有页码**；持久状态是阅读锚点 `{volumeId, chapterSn, verseSn, charOffset}`，页码只用于显示「3/12」。

- **顶栏控制码常驻**：`482 913` 等宽 20px、可复制、右侧 `⟳` 刷新（刷新不影响已连终端），并显示**剩余有效期倒计时**与码状态「可用 / 已使用 / 已过期」。
- **终端计数**：`2 个终端在线`，只读。0 时变橙色并展开一行引导：`让教室屏幕打开 cds.242500.xyz 并输入上面的控制码`。

#### 3.1.1 控制码的时效与消费（CO-2026-11-18-02 修订）

| 属性 | 值 | 说明 |
|------|----|------|
| TTL | **15 分钟** | 到点作废；倒计时常驻顶栏，`≤2 分钟` 转橙色提示"该刷新了" |
| 消费 | **单次** | 绑定成功即作废（`used`）。**一台终端一张码**；要接第二台屏幕，点 `⟳` 生成新码 |
| 刷新 | 手动 | 作废旧码；**已绑定终端不掉线**（绑定凭据与码解耦） |
| 格式 | 6 位数字（默认）／**8 位 Base32**（备选） | 由 `codeFormat` 配置。显示端有键盘则优先 8 位（空间 32^8≈1.1e12，抗枚举强约 100 万倍） |
| 限流 | 每 IP 10 次/分钟 | 边缘层（Worker）执行；超限 429 + 退避，**不提示"码不存在"**，一律"控制码无效或已过期" |
| 状态展示 | 可用 / 已使用 / 已过期 | 三种都给"下一步做什么"，不出现死界面 |

> 为什么不做"一码多端"：6 位码空间只有 10^6，允许一码反复使用等于把枚举窗口开到永久。单次消费 + 15 分钟 TTL 后，攻击者每天能猜的次数由限流封顶，且猜中也只能换来一张已作废的票据。多终端镜像的诉求由"多刷几张码"满足，界面不变（仍是计数）。

> **前置否决项**：若显示端是**无输入设备**（电视棒 / 纯投屏器），"显示端输码"整体不成立，本设计的 C2/C4/C5/C6 需换配对方式。**退路不是退回旧方向**：控制台出一次性部署令牌 `POST /display-token`（**48 小时**、绑一台；签发人＝控制台所属账号本人，见 §14 4c），运维装机时打开 `display.html#token=…` 烧进 `localStorage`，之后长期免输码。两条硬约束：一是 ~~令牌解决配对、不解决音频（形态 C 必须装机期开 autoplay 豁免）~~ **——本条已作废**（V2.1 的 D-A′ 把音频搬到控制页，display 无音频、不发声，autoplay 豁免不再需要；C 形态门槛只剩配对一道，见验收 C6）。**照 V2.0 旧文施工会把正常机器卡在「未开豁免不得验收」，勿按此执行**；二是**令牌卫生**（消费后 `history.replaceState` 清 URL、单次消费即撤销、48 小时未消费自动作废、装机记录不写明文）。这一条已在 11-18 上报 Jeremyzh，未定前按"显示端有键盘/触摸"推进。
- **场景切换不刷新**：三段 Tab 切换只切面板可见性 + 180ms 交叉淡入；数据已加载时不重新请求。

### 3.2 显示端（2 条）

| 路由 | 页面 | 说明 |
|------|------|------|
| `/#/` | **输码态**（仅当无本地码或码失效） | 6 位数字（或 8 位 Base32）输入 + 「确认」；上方一行**中性提示**「控制码 15 分钟内有效，过期请在控制台点 ⟳ 刷新」（原型里的“剩余 12:40”为同源模拟，**真机不提供**，见变更单异议 4）；下方 12px 灰字「长按 3 秒重置」；无其他链接 |
| `/#/display` | **内容态** | 单场景渲染 + 系统层；**零控件、无音频**。场景为 `standby` 时渲染**待机主题**（主题图 `theme` / 纯黑 `blank`），见 §3.4 |
| `/#/display?debug=1` | 调试叠层 | msgId / RTT / `state.report` / `styleVersion`（仅排障，生产隐藏） |
| `?reset=1` | 任意路径 | 清 `localStorage.cds.controlCode` 后停在输码态 |

**启动逻辑（伪代码）**

```
code = localStorage['cds.controlCode']
style = localStorage['cds.style']          // 先套样式，避免闪白/闪字
if (!code) → render CodeEntry
else → connect(); bindCheck(code)
        ok  → render Display（直接 lastFrame 或 idle）
        fail(code.invalid|code.unbound|code.revoked) → clearCode → CodeEntry + 提示条
```

### 3.3 单屏模式 `/#/screen`（V2.1 新增，显控一体）

| 项 | 设计 |
|----|------|
| 使用场景 | 一台电脑 + HDMI **复制**到投影/大屏（无扩展屏）。老师在这台电脑上同时"看内容"与"控制" |
| 鉴权 | JWT（与控制台同一登录态）。**不走控制码**——控制码是给陌生设备的，本机不需要。需 `POST /session/single` 用 JWT 换本机设备凭据（供 `state.report` 与心跳），接口见变更单 §6-1 |
| 布局 | 全屏渲染面（复用 `shared/render/*`）+ 底部迷你控制条：`待机 · 音乐 · 文章 · 板书`｜`⏮ ⏯ ⏭`｜`上一屏 · 下一屏`｜`投出/结束`｜`黑屏`｜`退出`（按场景只显示相关组） |
| 音频 | **它自己是控制页，所以 `<audio>` 在这里**（受 D-G 锚点约束） |
| 与多屏共存 | 可同时开单屏页 + 教室屏；两处渲染同一 `scene`；音频只在单屏页 |
| 退出 | 回 `/#/console`，**不**解绑凭据 |

> 为什么不做在 display.html 里：display 只持设备级凭据、无控制权，加控件＝提权；且会形成"设备凭据 / 用户 JWT"两套鉴权分支，安全评审必挂。

### 3.4 待机场景（V2.1 新增，默认态）

| 形态 | 画面 | 用途 |
|------|------|------|
| `theme` | 主题大图（`cover` + 压暗层 `dim` 0.25）+ 教室名 + 时间 | 默认；课前、课间、结束后 |
| `blank` | **纯黑**（不显示时间，仅留 1px 底部热区） | 老师在本机准备内容时，**不让学生看到下一条** |

- 切换：控制台待机面板 / 单屏模式迷你条 `黑屏` 按钮 → `display.standby {mode, themeId?}`。
- 默认形态由控制台记住（老师上周用黑屏，这周还是黑屏）。
- **设计意图（必读）**：复制模式下学生看到的就是老师屏幕，所以 `blank` 的真实作用是"不泄露内容"，**不是"看不出老师在操作"**——那需要扩展模式 + 手机控制（= 多屏模式）。见 §9.0。

### 5.2 显示端：一切走 CSS 变量（D-D）

`display.style` 下发的每个字段对应一个变量，显示端只消费变量：

| 变量 | 来源字段 | 示例 | 作用域 |
|------|----------|------|--------|
| `--cds-font-ui` | `fontFamily.ui` | `"Noto Sans SC", system-ui` | 全屏 UI（标题/提示） |
| `--cds-font-body` | `fontFamily.body` | `"Songti SC", serif` | 经文/正文 |
| `--cds-font-size` | `fontSizePx` | `72px`（**24–120，步长 4**） | `.content` 根 `font-size: var(--cds-font-size)`；歌词 `.lyric` 用 `calc(var(--cds-font-size) * .78)`，板书 `.paper` **直接用 `var(--cds-font-size)`**——V2.1.6 删掉 `min(…, 6.5vh)` 硬夹（6.5vh 在 1080p = 70.2px，字号 72px 以上对板书**全部无效**，与「远处看清」直接冲突）；装不下时按**步长 4** 逐档下调并回报实际生效值 |
| `--cds-font-scale` | `fontScale` | 兼容字段（缺省时 ×18 折算 px） | 只为旧载荷兜底；**UI 不再出现倍率** |
| `--cds-line-height` | `lineHeight` | `1.75` | 正文 |
| `--cds-fg` / `--cds-fg-muted` | `fg` / `fgMuted` | `#f2f4f8` / `#b8c0cc` | 正文 / 次级 |
| `--cds-bg` | `background.color` | `#000` | 页面底 |
| `--cds-bg-image` | `background.imageUrl` | `url(…)` | 背景图（`cover`，可空） |
| `--cds-align` | `align` | `left` \| `center` | 正文对齐 |
| `--cds-accent` | `accent` | `#8ab4f8` | 高亮节/歌词当前行 |

- 显示端基准 `html{font-size:18px}`；内容四周安全区 ≥5%（1920×1080 ≈96px）。
- `fontSizePx` **只作用于内容根**，不改系统层/提示条，避免布局崩。**V2.1.5 量程理由**：18px 基准 × 2.0 只有 36px、行高 1.75 → 63px/行，1080p 下 972px 可用高只能放 15 行，离 5–6 行差 3 倍；24–120 才能覆盖「一屏 4–23 行」。
- 存量迁移：旧 `fontScale`（0.8–2.0 → 14–36px）在大屏上全部不可用，控制台读不到 `fontSizePx` 时**一律置 72px**，不做等比换算。
- 样式变更**不打补丁**：整组变量重写 + 一条 `transition: font-size .2s ease, color .2s ease`（≤200ms），不刷新页面。
- 文章章内临时字号（`article.navigate.fontSizePx`）优先于全局：显示端用 `--cds-font-size-local` 覆盖，切章或样式下发时清空。**改动点**：原来写的是 `fontScale`，量程切换后若沿用会得到 21px。
- **物理约束（V2.1.6，必须让老师知道的取舍）**：1080p、四周 5% 安全区 → 可用高 ≈911px；行高 = `fontSizePx × 1.75`，另加每节段距（约 1.1em）。

  | `fontSizePx` | 行高 | 纯行数 | 实测「节首行起算」可放 |
  |---|---|---|---|
  | 72（默认） | 126px | 7 | **5 行**（2 节×2 行 + 下节首行 = 788px；第 6 行 914px 超） |
  | 96 | 168px | 5 | **4 行** |
  | 120（上限） | 210px | 4 | **2 行** |

  即「**字号上限 120px**」与「**一屏 5–6 行**」**不能同时满足**——这是算术，不是实现缺陷。要「远处看清」就接受更少行；要一屏多行就降字号。UI 必须把这个代价显式化（滑到 120px 时旁注「约 2 行/屏」），不要靠老师自己撞。

### 6.4 三个必须讲清楚的组件行为

**① `ProgressSlider`（控制台）** — 同 V1.0，保留：未拖动显示插值位置（300ms 刷新）；`pointerdown` 暂停被 `state.report` 覆盖；`pointerup` 发 `seek` 进"确认中"；3s 无 `ack` 或差值 >1500ms → toast「跳转未确认，已显示实际进度」并回落。

**② `VerseReader`（`article.navigate` 幂等）**
- 先比 `(volumeId, chapterSn)`，不同则拉章内容重渲染；相同则只处理锚点。
- `anchorVerseSn` 为空 → 章首；相同且已在视口 → **不滚动**（防重复下发漂移）；不在视口 → `scrollIntoView({block:'center'})`。
- `displayMode='page'` 按容器高算每屏节数（`ResizeObserver`），禁用连续滚动。
- **互斥补充**：切入文章场景时，若上次停在同章，直接用缓存的 `scrollTop` 还原，不重新拉接口。

**③ 场景切换（`SceneTabs` + 服务端仲裁）**
1. 点击 → 立即 180ms 交叉淡入（视觉），发 `POST /control/scene {scene, payload}`；
2. 服务端按 D-C 停旧场景、起新场景，回 `ack` + `state.report.scene`；
3. 回执 3s 未到 → Tab 回弹到 `state.report.scene`，toast「切换未确认」；
4. **进入"看内容"的画面会暂停音乐**（V2.1.2，依 Jeremyzh「板书时不要放配乐」）：点"文章"/"板书"时控制服务**先发 `player.pause`、收到 `ack` 再切画面**（`scene.set` 本身仍不隐式 pause，见 §9.2）；进入后 `audio.playing=false`、`positionMs` 冻结。`cast.end` / 回 `standby` **不自动续播**；点"音乐"Tab 或"继续"才恢复，且按 `positionMs` 重锚、**不重复 `play()`**。`article`/`cast` 下收到的 `player.play|resume` 一律 **409 `audio_blocked_by_scene`**。任何情形下**绝不** `audio.src=''`、不卸载 `<audio>`；
5. 切走文章 → 记 `scrollTop` + `anchorVerseSn`；切回还原；切走板书 → 保留草稿与 `castId`，不重新预签名（URL 未过期时）。

## 7. 状态机

### 7.1 连接 `connectionStore`（两端共用）

| 状态 | 进入 | UI | 副作用 |
|------|------|----|--------|
| `idle` | 初始 | 无徽标 | — |
| `connecting` | `mqtt.connect()` | 灰点「连接中」 | 8s 超时 → `offline` |
| `online` | `connack` | 绿点 | 订阅 `cmd`，起 ack 等待表 |
| `degraded` | 断开但重连中（≤3 次） | 黄点「轮询中」 | 控制台 2s 轮询 `/devices/{id}/state`；指令走 REST（`delivered:"polling"`） |
| `offline` | 重连 3 次失败 | 红点「离线」 | 轮询降 5s；控制按钮可点但提示 |

### 7.2 控制台会话 `sessionStore`（V2.0 重写）

`unauth → authed(no code) → codeReady → live(n terminals)`，任意态可 `codeInvalid`。

| 事件 | 动作 | 结果 |
|------|------|------|
| 登录 | `POST /auth/login` | `authed`，`GET /control-code` 拿码（无则自动生成） |
| 刷新码 | `POST /control-code/refresh` | 换码；**已连终端不掉线**；提示"新终端需用新码" |
| 终端接入 | `presence` 聚合 | `n+1`；n=0→1 时 toast「教室屏幕已连上」 |
| 终端掉线 | `presence online:false` | `n-1`；n=1→0 时顶栏转橙 + 提示"屏幕已断开" |
| 全部解绑 | `POST /devices/unbind {all:true}` | 所有终端回输码态（推 `code.revoked`） |
| 码被判无效 | `ack code.invalid` | 显示"控制码已失效，已自动换新码" |
| 绑定成功 | `ack code.bound` | 本码置 `used`，顶栏变「已使用 · 点⟳为下一台屏幕出码」；需要接第二台时刷新出新码（旧码作废，已连终端不动） |
| 码到期 | 本地倒计时归零 / 绑定 4102 | 顶栏转橙「已过期 · 点⟳刷新」；显示端同码输入一律按"过期"处理 |

> **没有** `occupied(4091)` 了：单控冲突是 V1.0"控制台抢设备"的产物；V2.0 里终端只认"它输的那个码"，不存在两台控制台抢同一台屏。

### 7.3 场景仲裁 `sceneStore`（V2.0 新增，服务端权威）

```
standby ⇄ music ⇄ article ⇄ cast          （V2.1：idle 更名为 standby，并成为默认态）
                     └── article.presenting（文章子态：已上屏）
```

| 事件 | 动作 | 结果 |
|------|------|------|
| 点 Tab | `POST /control/scene {scene}` | 视觉先过渡；`ack` + `state.report.scene` 落地 |
| 3s 无回执 | 重发 1 次（同 msgId）→ 仍无 | 回弹 + toast |
| 断线降级 | 轮询 `state.report` | 以轮询值为准；切场景按钮禁用直到 `online` |
| `state.report.scene` 与本地不一致 | 以服务端为准 | 静默纠正 + 记 warn |

**不变量（替换 V1.0 §9.2 四条）**
1. 任一时刻 `state.report` 里 `scene ∈ {standby, music, article, cast}`，且 `viewing` / `casting` **只有一个非空**；`standby` 时 `viewing`/`casting` 全空，`nowPlaying` **允许非空**（待机画面下放背景音乐是合法状态）。**`scene ∈ {article, cast}` ⟹ `audio.playing == false`**（V2.1.2）。
2. **V2.1.2 改写**：`scene ∈ {article, cast}` ⟹ `audio.playing = false`；进入这两态的唯一入口是**编排**（`player.pause` → 等 `ack` ≤1.5s → `scene.set`/`cast.start`）。`audio` 字段保留曲目与 `positionMs`，只是 `playing=false`；`standby` 允许 `playing=true`。任何情形下不得 `src=''`、不得 `load()`、不得卸载 `<audio>`；display 侧本就没有音频可操作。
3. 切回必须还原：音乐 `positionMs`、文章 `anchor`（`(volumeId, chapterSn, verseSn, charOffset)`，**不是页码**）、板书草稿。
4. `cast.*` / `article.*` 处理器内**不得**触碰音频锚点（限制"同一时刻只有一个"，不是"允许并存"）。

### 7.4 音乐 `playerStore`

```
idle ──play──> loading ──canplay──> playing ──pause──> paused ──resume──> playing
  ▲               │                    │                 │
  └──stop─────────┴──error────────────┴──(ended)─────────┴──> idle/ended
```

| 转移 | 触发 | 控制页副作用（音频锚点） | 显示端表现（仅歌词） |
|------|------|--------------|-----------|
| `→loading` | `player.play` | `audio.src=audioUrl; audio.load()`（在控制页） | 标题秒变，歌词占位 |
| `→playing` | `play()` resolve | 起本地 `timeupdate`（rAF 节流 100ms）；广播 `positionMs + durationMs`（**不带任何时间戳**） | 按插值推进高亮 |
| `→paused` | `player.pause`（**切走场景不触发本转移**，V2.1.1） | `audio.pause()`，记 `positionMs` | 冻在高亮行，不推进 |
| `→error` | 4xx/解码失败 | `ack{ok:false,code:4001}`，保留曲目与 `positionMs`（封面已删） | toast +「重试」 |
| `ended` | `audio.ended` | **不自动续播**（V2.1：① 音乐不需要自动播放）→ 停在 `ended`，高亮清单下一项等老师点；无下一项则回 `standby` | 停在末行 |

**`player.*` 仍是唯一能改 `audio` 的消息族。**

### 7.5 文章 `articleStore`

`idle → reading(volumeId, chapterSn) ⇄ searching(仅预选弹层)`

- 点预选条目 → `PUT /articles/position` + `article.navigate` → `reading`；
- 翻屏/翻节 → `article.scroll {direction:'next'|'prev', unit:'page'|'section', steps:1}`（只改视觉起点，不改 `chapterSn`）。`unit=page`＝视口前进 `N` 行；`unit=section`＝**把视口起点移到下一节首行，不是翻页、不是章内分屏**（语义见 §7.5.1）。越界停在末屏/末节并提示「已到章末」，不跨章；
- 步进按钮文案随 `unit` 变：`page` →「上一屏/下一屏」，`section` →「上一章/下一章」（数据里的「节」＝**章**，`chapterSn ± 1`）；`unit` 由老师在控制台切，**切 `unit` 不重发 `pageMap`**；
- 「整章一屏」（`sectionCount > 1` 时出现）＝逐步下调 `fontSizePx`（步长 4）到 `pageCount == 1`；**默认不动字号**，只有点了才缩；控制台显示实际生效字号；
- 切场景 → 存 `scrollTop`/锚点，**不 clear**；`article.clear` 才回 `idle`；
- **没有** `autoPlay / speed / volume`；误下发则忽略 + warn，不弹窗。

#### 7.5.1 分页与步进算法（V2.1.6 定稿，取代「按字符偏移二分」的旧表述）

Jeremyzh 11:47 用诗篇 23（7 节、每节折行后 2 行、视口 5 行）给了精确例子，**`unit=section` 既不是分页、也不是章内分屏，是「视口按节步进」**：

| 屏 | 内容 |
|----|------|
| 第 1 屏 | 节 1 两行 + 节 2 两行 + 节 3 第 1 行 |
| 点「下一节」→ 第 2 屏 | 节 2 两行 + 节 3 两行 + 节 4 第 1 行 |
| 再点 → 第 3 屏 | 节 3 两行 + 节 4 两行 + 节 5 第 1 行 |

每次把**视口起点移到下一节首行**、屏高不变（`N` 行由字号算出）、**允许底部露出半节**。相邻屏必然重叠（本例 3 行）——**这是预期，不是重复渲染的 bug**；验收按此判定，不要去「修」重叠。

**算法（5 步，开发照此实现）**

1. **整章渲染为连续视觉行流**：整章一次渲染，记每节首行在流中的行号 `verseLineIndex[k] = round(sectionEl.offsetTop / 行高)`。
2. **`N = floor(可用高度 / 行高)`**，`行高 = fontSizePx × lineHeight`（默认 1.75）；可用高度取 `.body` 的 `clientHeight`。
3. **`unit=page`**：`startLine = pageIndex × N`；屏数 `ceil(totalLines / N)`；节会被页边界切断（page 的固有行为）→ 页脚标「（续）」，下页页脚标「（续上）」。
4. **`unit=section`**：`startLine = verseLineIndex[sectionIndex]`；从该行起显示 `N` 行、到章末截断。**屏数 = 节数，不是 `ceil(行数/N)`**；`sectionIndex ± 1` 即上/下一节。
5. **越界**：末节首行 + `N` 行超出章末 → 显示到章末、余下留空，**不往上补**（回退起点会让末屏与上一屏重复）；`next` 到末节停住并提示「已到章末」，**不跨章**（跨章走 `article.navigate`）。

**定位实现**：不切片文本，整章 DOM 常驻，外层 `overflow:hidden`，内层 `transform: translateY(-startLine × 行高)`。这样段距只存在于一处 CSS，不会再漂移——**原型 V2.1.5 的裁行 bug 正来自「平行 ruler」**：ruler 里写 `margin:0 0 .9em`、正文写 `1.1em`，且 `getBoundingClientRect()` **不含 margin**，累加里根本没有段距（72px 下 3 个两行节测得 756≤911 通过，实渲染 756+3×79.2＝993.6，被 `overflow:hidden` 静默裁掉最后一行；7 个单行节测得 882、实渲染 1436）。**禁止再维护平行测量层**，一律读真实几何（`offsetTop/offsetHeight`）。

**屏数只用于显示、不预存**：`pageCount` 随 `unit` 现算；`unit=section` 时 UI 显示「节 3/7」，**不显示「3/12」**（section 模式屏概念不存在）。切 `unit` 不重发 `pageMap`。

**「续」标记只在 `unit=page` 出现**。`unit=section` 每屏都从节首开始，不需要「续」——V2.1.5「章内分屏标续」是 page 模式的补丁，不能当作 section 的语义（Jeremyzh 11:47 已明确否掉），**但也没有取消**：`unit=page` 下超长章仍标「续」。

**续行缩进（V2.1.6，我定的排版口径）**：`unit=page` 被切断后的续行若顶格（例子里「致缺乏。」），学生容易把它读成新的一节——续行加 **1 字符悬挂缩进**（该续行 `padding-left:1em`，配合 `text-indent:-1em` 只收首行），页脚保留小字「（续）」。Jeremyzh 若不要缩进，去掉这一条即可，不动结构。

**`pageMap` 形状（两处并存，不要混）**

- **计算结构**（display 内存，**不落库**）：`{anchor, totalLines, viewLines, verseLineIndex:[…]}`。**不存屏数组**——屏是 `unit` 的函数，预存会在切 `unit` / 改字号后过期。
- **上报摘要**（`state.report.pageMap`，5s 一条）：`{anchor, unit, pageIndex, pageCount, sectionIndex, sectionCount}` 六个标量，`pageCount`/`sectionCount` 由 display 按当前 `unit` **现算**；`unit=page` 时**也恒报节号**，否则控制台切 `unit` 后没有节号可显示。
- 变更单 §4.4 旧表里的 `pageMap = [{start:{verseSn,charOffset}, …}]`、以及「上报只含 `anchor/pageIndex/pageCount`」两处**均已作废**（字符偏移二分已被行流步进取代）。

### 7.6 板书 `castStore`

`idle → draft → previewing → casting → ending → idle`，任意态 `error` 回 `draft`。

- `text` 直接 `POST /cast/start`；`image/pdf` 先 `presign` 上传再 `cast.start(contentUrl)`；
- **V2.1.5 发送语义**：编辑区是**满高**（占面板剩余高度，约 80%），**双击即发送「光标所在行及其上方共 N 行」**（N 可选 3/5/8/10/全部，默认 5；不足 N 行取到首行；尾部空行 trim）；`dblclick` 要 `preventDefault`，并把选区收成光标（`preventDefault` 本身**不阻止**双击选词）；发送后 **3 秒撤销** toast；
- **草稿与已上屏必须是两个字段**：`cast.draft`（编辑区内容，随输入保存）与 `cast.text`（显示端正在显示的内容）。合成一个字段会在每次发送后把老师写好的整篇草稿替换成刚发出去的那几行（原型实测踩到）；
- 已投屏时再双击＝**同 `castId` 重发**，显示端原地替换 `.paper` 文本、不重建 DOM（不闪）；`cast.end` 用**已上屏**的 `text`，不用草稿；
- **`fullScreen` 字段不再下发**（V2.0 板书独占全屏）；
- `cast.end` 回 `idle` 场景（不是回上一场景——互斥下"结束板书"= 回到 Idle，由老师再选）；
- `ack 4004`/`4093` → 重新预签名 ≤2 次，仍失败 → toast + 回 `draft`。

### 7.7 预选 `preselectStore`（V2.0 新增）

### 7.8 样式 `styleStore`（V2.0 新增）

`default → editing → pushing → applied | failed`

- 值为受控枚举（字体从白名单选，不开放任意输入，防注入）；

## 9. 显示端渲染模型（互斥版）

### 9.0 两条物理约束（写给现场，不做成功能）

1. **显控一体 = HDMI 复制**：投影上是老师屏幕的逐像素副本，**包括迷你控制条、包括点"黑屏"的那一下**。所以"学生看不到我的操作"在这个形态下做不到；做到的是"内容不泄露"（`blank`）与"控制条尽量小、可淡出"。**「黑屏」的真实作用是「不让学生看到下一条内容」**（老师在本机准备下一篇经文时先黑屏），**不是防窥**——不要对外承诺"学生看不出老师在操作"。
2. **复制模式下无法同时显示 PPT 或其他软件**。三条出路：① 把 PPT 导出 PDF 走板书场景（推荐，最稳）；② PPT 窗口化（学生仍看到整个桌面，效果差）；③ 换扩展模式 + 手机控制（= 多屏模式，此时音乐按 D-A′ 前置条件降级）。**不对外承诺"一边放 PPT 一边控制"。**


### 9.1 图层（简化）

```
L2 SystemLayer   断线 / 重连 / 码失效                     z-50  非阻塞、半透明
                 （V2.1.1：display 不认识音频，音频锚点冲突提示只在控制页）
L1 ContentLayer  按 scene 只显示一个：Standby | Music | Article | Cast   z-10
   （V2.1：没有 <audio> 了，图层里不再有"常驻挂载的音频持有者"）
L0 无            待机不是"空"，是 L1 里的 StandbyScene（主题图或纯黑）
```

- **视觉上**只有当前 scene 可见（`display:none` + `aria-hidden`）。声音与画面解耦，但**解耦 ≠ 自由**（V2.1.2）：`music`→`standby` 音乐继续播；`music`→`article|cast` 由**编排**先 `player.pause` 再切画面（Jeremyzh「板书时不要放配乐」）；切回 `music` 按 `positionMs` 重锚。display 上没有 `<audio>` 可管——声音在控制页，由 `cds.audio.lease` 的持有者播，display 不知道音乐状态。
- 这不是 D-04 的"并存"：D-04 是同一台设备两个流程叠图层、两块内容同时可见；这里同一时刻只有一块内容可见，另一维度是**另一台设备上的声音**。
- 不使用多层透明叠加、不使用 `position:absolute` 堆全部场景（避免命中测试与无障碍污染）：非当前 scene `display:none` + `aria-hidden="true"`，`<audio>` 用 `<div hidden>` 包住但不卸载 React 树。

### 9.2 互斥不变量（code review 必查）

1. `scene.set(music→article|cast)` 指令本身**不隐式** `audio.pause()`（保住 `mqtt.md`「`cast.*` / `article.*` 无 `player.*` 副作用」）；暂停由**控制服务编排**在同一次用户动作里先发 `player.pause`、收到 `ack` 再发 `scene.set`/`cast.start`（`ack` 1.5s 未到**仍切画面**，控制台标「音乐未确认停止」+ 停止键）。`scene` 与 `audio` 是两个字段：仲裁器**不得**因切画面把 `audio` 置 `none`，也**不得**让 `scene ∈ {article,cast}` 时 `audio.playing=true`——该状态下收到 `player.play|resume` 一律 **409 `audio_blocked_by_scene`**（第二道闸，防客户端绕过编排）。
2. `scene.set(article|cast)→music` 时，歌词必须按控制页当前 `positionMs` **重锚**（不是从 0，也不是「续上刚才那帧」）；音频本身全程未停，不做 `play()` 第二次调用。
3. `article.clear` / `cast.end` 不得触发 `player.stop`，**也不得自动 `resume`**（回 `standby`，等老师再点继续/点"音乐"Tab）。
4. `cast.*` 处理器内无 `audio.*` 调用。
5. 三场景 DOM 不 teardown（切回不重新拉接口、不回到章首/曲首）。

### 9.3 控制台的"互斥"表现

| 场景 | 控制台表现 |
|------|-----------|
| 当前在音乐，点"文章" | Tab 立即高亮 + 内容区交叉淡入；**音乐先暂停**（先 `pause` 后切，见 §9.2），顶栏 now-playing 条显示「♪ 曲名（已暂停）· 04:12」；音乐面板内容保留（不消失，便于切回） |
| 当前在文章，点"板书" | 经文保留滚动位置；板书草稿原样 |
| 切回音乐 | 点"音乐"Tab 时若 `audio.playing=false`，编排发 `player.resume` + `scene.set(music)`；歌词与进度按当前 `positionMs` 重锚（误差 <1s），不从 0 开始 |
| 终端全部离线 | 三个 Tab 仍可点，但点击后按钮旁显示"离线，恢复后自动下发"（不排队多条，只保留最后一条） |
| 预选清单为空 | 每个场景面板给 `EmptyState`："今天还没排内容，点＋添加" |

## 10. 异常与降级

### 10.1 指令未确认
`ack` 3s 未回 → 同 `msgId` 重发 1 次 → 再 3s → toast「指令未确认」+ UI 回落到最近 `state.report`。

### 10.2 MQTT 不可用
`degraded`：顶部黄条「实时通道断开，正在用轮询同步（可能有 2s 延迟）」；指令照常可点，`delivered:"polling"` 时按钮旁黄点。

### 10.3 终端离线
N=0：所有控制按钮 `disabled` + 「教室屏幕未连接」；恢复后以 `state.report`（retain）全量对齐。

### 10.4 多终端部分在线
计数显示 `2/3 在线`（分母=已绑定上限内数量）；控制照常下发（fanout），以**最慢 ack** 作为"已生效"判据；超时只提示不阻断。

### 10.5 板书 URL 过期（4093 / ack 4004）
自动重签 → 重发 `cast.start`（新 `msgId`、同 `castId`）；两次失败 → "板书素材加载失败，请重新选择"。

### 10.6 音频锚点与手势（V2.1 全节重写）

> **本节不是分页。** 分页与 `unit=page|section` 的步进语义在 **§7.5.1**（V2.1.6）。按旧目录找「分页/翻页」会撞到这里，故留指路——V2.1.5 曾把分页算法要求写在本节，是错的位置。

> V2.0 的「输码手势内建 `AudioContext` → 静音探测 → 绑定」整节**删除**：display 已无音频，自动播放风险类别整体消失（变更单 §3）。同时删除形态 B「按遥控器任意键开始」例外——无音频可解锁。**不要以"暂不启用"的形式保留这段代码**，否则后人会当有效需求实现。

**三条约束（code review 必查）：**

1. **声音只从控制页出**。控制页 = `/#/console` 或 `/#/screen`。display 里出现 `new Audio` / `AudioContext` / `<audio>` → 直接打回。
2. **一首歌只有一个锚点**。`localStorage.cds.audio.lease = {owner, ts}`，owner 每 2s 续期，3s 未续视为过期；抢不到的一侧**静音跟随**，控制条显示「另一窗口正在播放，此处静音」。不做 → 现场是"投了有回声/两轨错位"，最难查的一类。
3. **时基用显示端本地单调时钟**（V2.1.1 修正；原「服务端打点」写法作废）。`player.play` 只带 `positionMs`、`durationMs`，**不带 `startedAtEpochMs`**。display 收到 `play` 时：`t0 = performance.now(); base = positionMs + delayMs; pos(t) = base + (performance.now() - t0)`，rAF 推进。
   - **重锚三档死区（V2.1.3 统一口径）**：每 5s 收到 `state.report.positionMs` 时算 `Δ = reported − pos(now)`。`|Δ| < 80ms` → **忽略**（落在测量噪声内，且每 5s 微跳肉眼可见）；`80ms ≤ |Δ| ≤ 300ms` → **慢追**（每帧向目标靠 10%、单帧 ≤5ms，约 2s 收敛，不跳）；`|Δ| > 300ms` → **直接跳**（`base = reported; t0 = performance.now()`）。**这三档是唯一口径**，取代此前文档里的 200ms、250ms 与开发「80/300 死区」三种写法；任何一处引用都指向本节。
   - `delayMs`（单程）由**控制页单侧测**：发 `play` 记 `sendT`、收 `ack` 记 `recvT`，单程 `= (recvT − sendT) / 2`。取**最近 3 次的中位数**（单次在教室 Wi-Fi 抖一下就能把歌词推后约 1s），并 **clamp ≤300ms**；首播无样本时取 `delayMs = 0`（宁早 100ms 不晚——早了下一档重锚会拉回，晚了则永远落后）。
   - **为什么不能用 `startedAtEpochMs`**：服务端打点只消掉「控制台↔服务端」钟差，**消不掉「显示端↔服务端」钟差**。`positionMs + (Date.now() - startedAtEpochMs)` 里的 `Date.now()` 是**显示端**的钟——D-1 的电视棒/盒子没有 NTP，钟可差几十秒到几分钟，且随开机/校时跳变，表现是歌词整段跳或一路爬。这条错误不会在开发机上暴露（同机同钟），只在真机出现。
   - 残余误差只剩「服务端→显示端」单程网络延迟（一次性、约 10–100ms），**不随运行时间累积**，5s 重锚可吸收。
   - **页面重载后 `performance.now()` 归零**：不得从旧 `t0` 续算，必须先 `GET /devices/{id}/state` 拿当前 `positionMs` 再重锚（与 §10.9 断网重启同一路径）。
   - **`lines[]` 只在 `trackId` 变化时下发**，不随 5s 回执重传全量 LRC（单连接会被打爆）。

**移动端控制页**：`visibilitychange → hidden` 立即 `pause` 并记位置；回前台**不自动续播**（防教室突然出声），提示「已暂停，点播放继续」。手机/平板默认音乐置灰（见 D-A′ 前置条件）。

**部署前提（写给运维与现场）**：控制页所在设备必须接场地音响——单屏模式走 HDMI 回传、笔记本走线路输出、或蓝牙。这条不在代码里能兜住。


### 10.7 第三方音乐不可用
列表来自本地 D1；详情失败用缓存字段降级；`audioUrl` 取不到 → toast「该曲目音频不可用」，不进 `loading`。

### 10.8 控制码失效 / 被撤销（V2.0 新增，P0）
- 触发：`ack code.invalid` / `code.unbound` / `code.revoked` / 绑定时 401/403。
- 显示端：内容淡出 → `CodeEntry`，提示条**「控制码已失效，请重新输入」**（保留 8s，不自动消失）；清 `localStorage.cds.controlCode`。
- 过期分支文案单独一条：**「控制码已过期，请在控制台刷新后重新输入」**（过期与失效/撤销要区分，老师才知道该找人刷新码还是该重新输码）。
- 提交失败的文案**全部由服务端 `reason` 驱动**，前端不本地猜：`expired` →「控制码已过期，请在控制台刷新后重新输入」；`used` →「该控制码已被使用，请重新输入」；`invalid` →「控制码无效，请与控制台核对」；`rate_limited` →「尝试过于频繁，请 1 分钟后再试」。
- **不得**为显示剩余有效期而新增“按码查状态”接口（见变更单异议 4）；倒计时只在控制台。
- 控制台：`presence` 掉到 0 + toast「教室屏幕已断开，请确认屏幕上的控制码」。
- 隐藏重置：长按 3 秒（环形进度）/ `?reset=1`。

### 10.9 显示端断网重启
有码 + 有 `cds.style` + 有 `cds.lastFrame`：先渲染最后一帧（防黑屏）→ 连上后以 `state.report` 对齐；无网 60s 后系统层提示「网络异常，正在重连」。

## 12. 可用性 / 键盘 / 无障碍

**控制台快捷键**（输入框聚焦时禁用）：`Space` 播放/暂停；`←/→` 文章上一屏/下一屏、音乐 -5s/+5s；`↑/↓` 音量 ±5；`/` 聚焦预选搜索（仅编辑态）；`1/2/3` 切三个场景；`Esc` 关闭弹层。

**无障碍**：对比度 ≥4.5:1；触控目标 ≥44×44px；状态变化 `aria-live="polite"`（含终端计数）；图标按钮有 `aria-label`；状态不只靠颜色（点 + 文案）。

**单屏模式 `#/screen`（V2.1）**：迷你控制条 3s 无操作淡出至 12%，鼠标移至底边 80px 或按 `Esc` 唤回；控件 ≥44×44px；`Tab` 顺序限定在控制条内；切场景用 `1–4`。**注意：复制模式下学生看得见控制条与黑屏动作**（见 §9.0），本条不承诺"学生看不到操作"。
