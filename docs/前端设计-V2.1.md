> ### 口径红线（开发不得自行加回）
> 1. 文章模块是**人工阅读导航器**，不是播放器：**没有**朗读 / 语速 / 音量 / 自动播放，`article.*` 与 `/articles/*` 里不出现 `play`、`pause`、`speed`、`volume`、`autoPlay`。
> 2. 音乐播放只有 `player.*` 一套控制。
> 3. **画面互斥；"看内容"的画面下不得有声**（V2.1.2 定稿，依据 Jeremyzh「板书时不要放配乐」）：同一时刻 display 只渲染**一个**画面场景（`standby`/`music`/`article`/`cast`）。D-04 的"同一个 display 上图层并存"**永久废弃**（图层栈只有内容层 + 系统层，V2.0 的 L0–L3、`fullScreen`、`MiniPlayerBar` 都不回来）。音乐仍是**独立音轨**（声音在控制页，display 不知道音乐在播），但**`article` / `cast` 下不得为 `playing`**：进入这两态时由控制服务**先 `player.pause`、收到回执再切画面**；`cast.end` / `article.clear` 回 `standby` **不自动续播**；`standby` 允许背景音乐。V2.1.1 曾写"`article`/`cast`/`standby` 都允许背景音乐"，已作废。详见变更单 §4.5。
> 4. **控制在控制台，显示端只执行**：显示端除首次输码外，没有任何交互控件。
> 5. **控制码由控制台生成**，显示端输入。禁止再出现"显示端出码、控制台输码"的实现。**V2.1.26（CO-05）补充：控制码是用户级、存库、长期有效的口令——不是一次性票据（没有 TTL / 没有「已使用」/ 不自动换码）；判定「这条绑定还有效吗」只能凭设备凭据，不得按码查。**
> 6. **音频锚点＝控制页**（V2.1）。`<audio>` 只存在于控制页（console / `#/screen`）；**display 里不得出现 `Audio` / `<audio>` / `AudioContext`**（`rg -i 'audio' src/display/` 只允许 `?debug=1` 的调试字段）。声音从哪台设备出＝控制页跑在哪台设备。
> 7. **待机是场景，不是空白**（V2.1）。`scene ∈ {standby, music, article, cast}`，`standby` 是默认态，有两个形态：主题图 `theme` / 纯黑 `blank`。任何"结束"动作都落回 `standby`，不落回"等待控制台"。

## 1. 两套界面，两个入口

| 端 | 使用者 | 形态 | 入口 | 职责 |
|----|--------|------|------|------|
| **控制台 console** | 教师 | 手机 / 平板 / 桌面浏览器 | `/#/login` → `/#/console` | 出控制码、挑今日内容、切三个场景、下发样式；**一屏搞定** |
| **显示端 display** | 无人 | 教室大屏 1080p | `/#/`（输码态）→ 内容态 | 输一次码，然后**纯执行**：渲染内容、套样式；**无 audio 元素、永不发声**（V2.1） |

**两条架构决策（继承 V1.0，仍有效）：**

- **D-A′ 音频在控制页播放（V2.1 反转，原 D-A 作废）。** `<audio>` 只存在于**控制页**（`/#/console` 或单屏模式 `/#/screen`）；display 只渲染歌词，**不解码、不加载音频**。
  - 推论 1：控制页进度来自本地 `audio.currentTime`（不再需要 5s 回执插值），拖动即 `seek` 本地。
  - 推论 2：display 的歌词高亮改由**本地单调时基插值**驱动（`pos = base + performance.now() - t0`，`t0` 在收到 `play` 时取，见 §10.6 第 3 条），不再有音频时钟，**也不使用任何 epoch 时间戳**（display 的墙钟不可信，见 V2.1.1）。
  - 推论 3：**声音只从控制页那台设备出**。这条是部署前提，不是实现细节：老师用手机控制时，教室听不到（详见 V2.1 变更单 §3.2）。
  - **前置条件**：音乐场景可用 ⟺ 控制页跑在接了场地音响的那台机器（单屏模式的电脑 / 接了线路输出的笔记本）。手机/平板控制页的音乐面板默认置灰并说明原因（**临时口径**：变体 2「手机当遥控器、电脑出声」一旦立项，置灰改为「能发指令、音频宿主不在此」，见 §14-9）。
- **D-B 控制台不乐观猜状态。** 任何控制指令等 `ack` 或 `state.report` 才更新权威状态；`ack` 3s 超时才提示。

**V2.0 新增架构决策：**

- **D-C 互斥由服务端仲裁（只管画面）。** 前端只发"我要切到某画面场景"，由服务端保证"旧**画面**先停、新画面再起"，`state.report.scene` 是唯一真相。前端**不做**本地抢先切换（允许 180ms 视觉过渡，但状态以回执为准）。**仲裁器不碰音轨，但"看内容的画面"必须无声**（V2.1.2）：`scene` 与 `audio` 是两个字段，仲裁器**不得**因切画面把 `audio` 置 `none`（要保留曲目与 `positionMs`）；进入 `article`/`cast` 的静音是**编排层显式发的 `player.pause`**（先 pause、收到回执再切画面），不是仲裁器隐式改音频、也不是显示端推断。
- **D-D 样式是数据，不是代码。** 显示端的字体/字号/行高/颜色/背景全部来自 `display.style` 下发的值，写进 CSS 变量；显示端不硬编码任何主题。
- **D-E 控制码是「每用户一张、长期有效的口令」（CO-2026-11-18-05）。** 管理员登录后每个用户一张码、存在数据库；同户多台屏幕**共用**同一张码，同一账号开多个控制端页签也共用。码**不被消费**（绑一台不会失效）、**不自动过期**（只在控制端手动更新时更换）。终端集合在控制台是**可展开的列表**（可逐台「移出接管」），不是只读计数。判定「这条绑定还有效吗」只能凭**设备凭据**，不得按码查。
- **D-F 码必须可枚举防御。** **8 位数字**（10^8）＋ 边缘按 IP 限流 10 次/分钟（不能按码限流：攻击者猜的是不存在的码，没有行可累加）＋ **一律回「控制码无效」、不区分「不存在 / 已被更新」** ＋ **不得新增按码查状态的接口**（`GET /control-code/{code}` 一类等于一条永不关闭的枚举通道）。码长期有效 ⇒ 不能靠短时效兜底，穷举防线就是这三条。

**V2.1 新增架构决策：**

- **D-G 音频锚点唯一。** 同一 origin 同一时刻只允许一个音频锚点（`localStorage.cds.audio.lease` + 2s 心跳，3s 未续作废）。抢不到的一侧静音跟随并在控制条标注。防的是"console 与 `#/screen` 同时开着导致双声/回声"。
- **D-H 单屏模式是第三种控制形态，不是显示端加控件。** `/#/screen`（console 域、JWT）＝全屏渲染面 + 迷你控制条；`display.html` 保持纯被动、零控件、只持设备凭据。两者**复用同一个渲染器**（`src/shared/render/*`），鉴权不分叉、不复制渲染代码。
- **D-I 分页只在渲染端算。** 分页结果 `pageMap` 由 display / 单屏页实测产出；控制台只发"下一屏/上一屏"，**不持有页码**；持久状态是阅读锚点 `{volumeId, chapterSn, verseSn, charOffset}`，页码只用于显示「3/12」。

#### 3.1.1 控制码：每用户一张、存库、长期有效（CO-2026-11-18-05 重写）

| 属性 | 值 | 说明 |
|------|----|------|
| 归属 | **用户级** | 管理员登录后每个用户一张控制码（`control_codes(user_id, code, rotated_at)`）。该用户的多台屏幕**共用同一张码**；同一账号开多个控制端页签也共用。 |
| 时效 | **长期有效** | **没有 TTL、没有倒计时、没有自动过期、没有「已使用」**。V2.1.23 那一层（15 分钟 TTL、单次消费、到期自动换码、绑定后自动续码）**整体删除**——来源 CO-2026-11-18-05，Jeremyzh 20:11 原话「控制码存在数据库」「控制码不再自动过期（可手动触发更新）」。 |
| 格式 | **8 位数字** | 10^8 配「同 IP 1 分钟第 11 次」限流，单 IP 穷举约 19 年。~~6 位数字／8 位 Base32~~ **作废**：码不再是一次性票据，不需要靠短时效兜底。 |
| 更新（⟳） | 手动 | ＝**重置接管**：换新码 **并撤销该用户全部绑定**（`device_bindings.revoked_at = now`）⇒ 已接管的屏幕 3s 内回输码页（在线屏）。**只换字符串不撤绑定＝缺陷**：旧屏会用旧码继续被控。 |
| 移出单台 | 手动 | 撤销**那一条**绑定（`device_bindings.revoked_at`）＋一条审计；**不是封禁**——可立即用同一张码重接。文案「已移出接管」。 |
| 有效性判定 | **按设备凭据，不按码** | 显示端只问「我这条绑定还有效吗」，凭 `Device` 凭据请求 `GET /devices/me`（`api.md` §4.6），服务端只回 `state ∈ {bound, revoked, unbound}`（`unbound` ＝ 从未绑定）与 `reason`。**刷新码与踢单台共用这一个接口**；该接口不接受以码为入参，因此无法被用来枚举。 |
| 限流 | 每 IP 10 次/分钟 | 边缘层执行；超限 429，一律「控制码无效」，不区分「不存在 / 已被更新」。 |

> **为什么从「一台屏一张码」改成「一户一张」**：一屏一码时，「这张码没人用了」和「这个账号没有控制端了」是两件事，显示端自己判不出来——于是有了 V2.0.2–V2.1.22 的「已连终端不掉线」，屏会变成没人能控的孤儿。改成用户级 + 存库之后，判据只剩一条：**显示端存的码在库里查不到 ⇒ 没有控制端能控它 ⇒ 回输码页**。这是 CO-05 的全部逻辑，不需要再叠加票据状态机。

> **前置否决项（不变）**：若显示端是**无输入设备**（电视棒 / 纯投屏器），「显示端输码」整体不成立，需换配对方式（控制台出一次性部署令牌，48 小时、绑一台）。V2.1 的 D-A′ 已把音频搬到控制页，C 形态的门槛只剩配对一道（验收 C6）。这一条仍在 Jeremyzh 桌上，未定前按「显示端有键盘/触摸」推进。

### 3.2 显示端（2 条）

| 路由 | 页面 | 说明 |
|------|------|------|

**启动逻辑（伪代码）**

```

#### 3.4.1 屏端隐藏退出：右下角长按 3 秒 → 二次确认 → 解绑（V2.1.43）

> 来源：Jeremyzh 2026-11-18 21:57（经 Chief 转达）「隐藏退出＝右下角长按 3 秒＋二次确认」；协议侧**零新字段**（确认态不下发、不上报），接口 `POST /devices/me/release`（`api.md` §4.3.1），快照 `{state:'revoked',reason:'unbind'}`（`mqtt.md` §4.6.5 ⑮）。

| 项 | 规定（全部可判，判据见验收 V2.1.43 七条） |
|---|---|
| 热区 | 右下角**不可见**热区（建议 88×88 CSS px、`position:fixed`）：**不出按钮、不出图标、不出可见文案**，学生不应发现入口 |
| 计时 | `pointerdown` 起算 **3000ms**；环形进度只画在热区内（不可见热区＝**不画**，改为无反馈，避免暴露入口） |
| 取消 | 以下任一发生即清零、**不弹框**：① `pointermove` 累计位移 **>10px**；② 页面发生滚动（`scroll` 事件，含命中 `.paper` 竖向滚动条轨道）；③ `pointerup`/`pointercancel`/`pointerleave` 早于 3000ms |
| 吞事件 | 热区内 `pointerdown/move/up`、`contextmenu`（Android 平板长按会弹系统菜单）、`selectstart` 一律 `preventDefault`；热区 `touch-action:manipulation`、`user-select:none`、`-webkit-touch-callout:none` |
| 避让 | ① 不得与输码页 `.reset-hint`（`display.html` L40，右下角 12px「长按 3 秒清除本地码」）**重叠或抢事件**——输码态该热区不绑解绑动作；② 不得与板书 `.paper` 竖向滚动条轨道重叠——**命中轨道不计时**（`mqtt.md` V2.2.32 同日补的避让规则），否则老师滚讲义会当场弹解绑框、确认按钮正好在手指下。**V2.1.45 补实现口径（可判）**：内缩量＝**实测**轨道宽（`paper.offsetWidth − paper.clientWidth`）＋2px，且**无条件内缩**（`scrollbar-gutter:stable` ⇒ 轨道常驻，**不得**写成「出现滚动条时才内缩」，否则同一块屏在有/无溢出的板书上能按到的地方不一样，`mqtt.md` V2.2.36）；轨道**未贴到视口右缘**时内缩 0（如原型 `.paper{max-width:74vw}` 居中）。另须在 `pointerdown` 里**按坐标再判一次**：`clientX ≥ innerWidth − 轨道宽 − 2` ⇒ 不计时（平台滚动条可能比内缩量更宽）。 |
| 二次确认 | 文案「确定解除本屏接管？解除后需重新输入控制码」；**默认焦点在「取消」**（连按 Enter 不得确认）；`Esc` 可关闭；`role="dialog"` + `aria-modal="true"` |
| 确认后 | `POST /devices/me/release`（设备凭据、**无请求体**）→ **无论 `released:true` 还是 `released:false` 都回输码页**并按已解绑处理（`false` ＝「现在本来就没绑定」，**不是失败**：不报错、不弹 toast、不留在内容页） |
| 竞态 | 确认框打开期间若收到 `cds/v1/d/{deviceId}/bind` 的 `state='revoked'` 快照 ⇒ **直接关框回输码页**，**不再发** `release`（判据：网络面板该请求 0 次） |
| 不复用 | 输码态的「长按 3 秒」＝**清除本地码**（`?reset=1` 等效，只清 `cds.bound`/`cds.boundAt`/`cds.displayBeat`、**不动** `deviceToken`；**V2.1.54**：原写 `cds.controlCode`，该键不存在），内容态才是「解绑」。同一手势两种结果，**文案与实现都不得混用**：输码态写「清除本地码」，不写「解绑」 |

- 样式变更**不打补丁**：整组变量重写 + 一条 `transition: font-size .2s ease, color .2s ease`（≤200ms），不刷新页面。
- 文章章内临时字号（`article.navigate.fontSizePx`）优先于全局：显示端用 `--cds-font-size-local` 覆盖，切章或样式下发时清空。**改动点**：原来写的是 `fontScale`，量程切换后若沿用会得到 21px。
- **物理约束（V2.1.6，必须让老师知道的取舍）**：1080p、四周 5% 安全区 → 可用高 ≈**902px**（V2.1.12 实测 `.body.clientHeight`：整块 972 减页眉页脚 70）；行高 = `fontSizePx × 1.75`，另加每节段距（约 1.1em）。

  | `fontSizePx` | 行高 | 首屏（整节下移，诗篇 23、`c=12`） | 全章屏数 |
  |---|---|---|---|
  | 72（默认） | 126px | **4 行**（节 1+节 2 = 583.2px；加节 3 需 914.4px 超） | 3 |
  | 96 | 168px | **4 行**（777.6px） | 5 |
  | 120（上限） | 210px | **2 行**（一节 420px＋下一节需 972px 超） | 6 |

  即「**字号上限 160px**」与「**一屏 5–6 行**」**不能同时满足**——这是算术，不是实现缺陷；而且「一屏几行」不只由字号决定，**每行字数 `charsPerLine` 与行距同样决定**（§7.5.3）。UI 必须把这个代价显式化（滑到大字号时旁注当场变），不要靠老师自己撞。**旁注的数字不写死**：取 display 上报的 `pageMap.viewLines`（**首屏**完整行数），控制台只显示不自己算（见 §7.5.1 与变更单 §4.9）。
  > V2.1.6–V2.1.9 的「72→5 行 / 96→4 / 120→3」是**填满优先**（把自身不到一屏的节切开填满）算出来的，与 `mqtt.md` V2.2.8 定死的「整节下移」冲突，**作废**；同一首诗篇 23、`c=8` 两种规则分别得 5 屏与 4 屏，会让人以为屏数随实现者变。

#### 6.2.1 排版属性是「公共属性」：只有一个入口，在页面底部控制栏（V2.1.40）

Jeremyzh 21:40 ①：「文章的字号、行距，属于公共属性，放到页面底部的控制栏里面去」。落地口径：

| 位置 | 放什么 | 硬约束 |
|---|---|---|
| **底部控制栏**（`StylePanel`，默认折叠 `details`） | 正文字体 / **字号** / **行高** / 对齐 / 正文色 / 背景色 / 下发 | **唯一入口**。折叠时 `summary` 必须显示当前值（`字体 · 字号或「自动」 · 行高 · 每行`）；原型 L8xx 本来就有，别在重构时丢掉 |
| 文章面板 `.readbar` | **每行字数** + 只读回显（字号/行高/首屏行数）+ 上一屏 / 下一屏 / 整章一屏 / 投屏 | **不得**再有字号/行高滑块（两份控件＝两份真相，且会各写一次 `cds.style`）；`#rLines` 必须常驻，不能被预览说明挤到滚动区外 |
| 音乐 / 板书面板 | 不重复排版控件 | 同上：改一次下发一次，四个场景共用一份状态 |

三条会实际咬人的衍生约束：

1. **字号拖动即锁定**。`fontSizePx` 默认 `auto`（显示端按屏高派生）。删掉面板里那只滑块后，**控制栏的滑块必须自己把 `'auto'` 锁成数字**——原实现是靠面板那只滑块的 `input` 处理器做这件事；只搬控件不改锁值，`auto` 档下拖了屏上不变，就是「看着没被控制」。
2. **`c_max` 联动不能丢**（V2.1.10）。每行字数上限是字号的函数（`min(24, floor(availW ÷ 字号))`）：字号一改，`rChars.max` 必须当场重算，当前值 `clamp` 到新上限并标「（上限）」。
3. **回显不能落后一拍**。面板里的字号/行高是只读回显，控制栏一改就同帧同步；否则老师会以为刚才那一下没生效。

> 同轮另三条：② 板书改竖向滚动（§6.2 `CastControl`、§7.6）；③ 歌词连续纵向居中（§7.4）；④ 屏端右下角**长按 3 秒 → 二次确认 → 自行解绑**（`POST /devices/me/release`，§3.4 待机面板有入口提示）。⑤ 非登录用户绑码**方向未定，不开工**（§14）。

### 6.4 三个必须讲清楚的组件行为

**③ 场景切换（`SceneTabs` + 服务端仲裁）**

3. 回执 3s 未到 → Tab 回弹到 `state.report.scene`，toast「切换未确认」；

5. 切走文章 → 记 `scrollTop` + `anchorVerseSn`；切回还原；切走板书 → 保留草稿与 `castId`，不重新预签名（URL 未过期时）。

## 7. 状态机

### 7.1 连接 `connectionStore`（两端共用）

| 状态 | 进入 | UI | 副作用 |
|------|------|----|--------|
| `idle` | 初始 | 无徽标 | — |
| `connecting` | `mqtt.connect()` | 灰点「连接中」 | 8s 超时 → `offline` |
| `online` | `connack` | 绿点 | 订阅 `cmd`，起 ack 等待表 |
| `degraded` | 断开但重连中（≤3 次） | 黄点「轮询中」 | 控制台 2s 轮询 `/devices/{id}/state`；指令走 REST（`delivered:"polling"`） |
| `offline` | 重连 3 次失败 | 红点「离线」 | 轮询降 5s；控制按钮可点但提示 |

### 7.2 控制台会话 `sessionStore`（V2.0 重写）

`unauth → authed(no code) → codeReady → live(n terminals)`，任意态可 `codeInvalid`。

| 事件 | 动作 | 结果 |
|------|------|------|
| 登录 | `POST /auth/login` | `authed`，`GET /control-code` 拿码（无则自动生成） |
| 刷新码（更新控制码＝重置接管） | `POST /control-code/rotate` | 换码 **＋撤销该用户全部绑定**（`device_bindings.revoked_at`，**覆盖** `cds/v1/d/{deviceId}/bind` 上的保留快照为 `{state:'revoked',reason:'code_rotated'}`）；**已接管的屏 3s 内回输码页**，`article`/`cast` 先回 `standby`；二次确认含台数「会让 N 台屏幕回输码页」（N 取 `GET /devices/list` 的 `online:true` 计数，不取本机缓存） |
| 移出单台 | `POST /devices/{id}/revoke` | 撤销那一条绑定（`device_bindings.revoked_at`）+ 一条审计，覆盖该设备 `bind` 快照为 `{state:'revoked',reason:'kicked'}`；只这一台回输码页，**不封禁**、可立即用同一张码重接 |
| 终端接入 | `GET /devices/list` / `presence` | `n+1`；n=0→1 时 toast「教室屏幕已接管」。**码不消费**：第 2/3 台输同一张码直接接管 |
| 终端掉线 | `presence online:false` | `n-1`；n=1→0 时顶栏转橙 + 提示"屏幕已断开" |
| 全部解绑 | `POST /devices/unbind {all:true}` | 所有屏回输码页（清该用户全部 `bind` 快照（retained 空 payload）） |
| 绑定成功 | `ack code.bound` | 只登记设备，**码不变、不出新码**（V2.1.23 的「自动续码」随 CO-05 删除） |
| ~~码到期~~ | — | **整行删除**：码长期有效，没有到期这回事（CO-05） |

> **`occupied(4091)` 是换过语义，不是消失了**（V2.1.31 更正；本节此前写"没有 4091 了"，与 `api.md` §4.2/§9 冲突）：
> - V1.0 的"两台控制台抢同一台屏"确实不存在，那部分作废；
> - CO-05 下 **4091 ＝ 同一个 `deviceId` 已被其他用户接管**（`api.md` V2.2.5 收窄后的口径）。同户第 2/3 台是**另一个 `deviceId`**，永不触发；同户"移出后重绑"也不触发。
> - **P1 未定（等 Jeremyzh 一句）**：屏被 A 绑着、A 已离职/换班，B 想接这台屏 ⇒ 现口径只能由 A 先"移出接管"，否则**屏砖化**（管理员解绑手段未定义）。跨用户重绑走"屏上二次确认接管"还是"一律拒绝 + 需管理员解绑"，未定前按现行 fail-closed 实现（回 4091），**不得擅自放开**。

### 7.3 场景仲裁 `sceneStore`（V2.0 新增，服务端权威）

standby ⇄ music ⇄ article ⇄ cast          （V2.1：idle 更名为 standby，并成为默认态）
                     └── article.presenting（文章子态：已上屏）
```

| 事件 | 动作 | 结果 |

| 点 Tab | `POST /control/scene {scene}` | 视觉先过渡；`ack` + `state.report.scene` 落地 |

| `state.report.scene` 与本地不一致 | 以服务端为准 | 静默纠正 + 记 warn |

**不变量（替换 V1.0 §9.2 四条）**
1. 任一时刻 `state.report` 里 `scene ∈ {standby, music, article, cast}`，且 `viewing` / `casting` **只有一个非空**；`standby` 时 `viewing`/`casting` 全空，`nowPlaying` **允许非空**（待机画面下放背景音乐是合法状态）。**`scene ∈ {article, cast}` ⟹ `audio.playing == false`**（V2.1.2）。
2. **V2.1.2 改写**：`scene ∈ {article, cast}` ⟹ `audio.playing = false`；进入这两态的唯一入口是**编排**（`player.pause` → 等 `ack` ≤1.5s → `scene.set`/`cast.start`）。`audio` 字段保留曲目与 `positionMs`，只是 `playing=false`；`standby` 允许 `playing=true`。任何情形下不得 `src=''`、不得 `load()`、不得卸载 `<audio>`；display 侧本就没有音频可操作。
3. 切回必须还原：音乐 `positionMs`、文章 `anchor`（`(volumeId, chapterSn, verseSn, charOffset)`，**不是页码**）、板书草稿。
4. `cast.*` / `article.*` 处理器内**不得**触碰音频锚点（限制"同一时刻只有一个"，不是"允许并存"）。

### 7.4 音乐 `playerStore`

```
idle ──play──> loading ──canplay──> playing ──pause──> paused ──resume──> playing
  ▲               │                    │                 │
  └──stop─────────┴──error────────────┴──(ended)─────────┴──> idle/ended
```

| 转移 | 触发 | 控制页副作用（音频锚点） | 显示端表现（仅歌词） |
|------|------|--------------|-----------|
| `→loading` | `player.play` | `audio.src=audioUrl; audio.load()`（在控制页） | 标题秒变，歌词占位 |
| `→playing` | `play()` resolve | 起本地 `timeupdate`（rAF 节流 100ms）；广播 `positionMs + durationMs`（**不带任何时间戳**） | 按插值推进高亮 |
| `→paused` | `player.pause`（**切走场景不触发本转移**，V2.1.1） | `audio.pause()`，记 `positionMs` | 冻在高亮行，不推进 |
| `→error` | 4xx/解码失败 | `ack{ok:false,code:4001}`，保留曲目与 `positionMs`（封面已删） | toast +「重试」 |
| `ended` | `audio.ended` | **不自动续播**（V2.1：① 音乐不需要自动播放）→ 停在 `ended`，高亮清单下一项等老师点；无下一项则回 `standby` | 停在末行 |

**`player.*` 仍是唯一能改 `audio` 的消息族。**

### 7.5 文章 `articleStore`

`idle → reading(volumeId, chapterSn) ⇄ searching(仅预选弹层)`

- 点预选条目 → `PUT /articles/position` + `article.navigate` → `reading`；
- 翻屏/翻节 → `article.scroll {direction:'next'|'prev', unit:'page'|'section', steps:1}`（只改视觉起点，不改 `chapterSn`）。`unit=page`＝视口前进 `N` 行；`unit=section`＝**把视口起点移到下一节首行，不是翻页、不是章内分屏**（语义见 §7.5.1）。越界停在末屏/末节并提示「已到章末」，不跨章；
- 步进按钮文案随 `unit` 变：`page` →「上一屏/下一屏」，`section` →「**上一节/下一节**」。**「节」＝经节（`verseSn`），不是章**——依据 Jeremyzh 11:47 的例子：他在诗篇 23 一章之内点「下一节」，视口就从节 1 移到节 2。V2.1.6 写的「节＝章」作废（那会把一章之内无法步进）。跨章是另一个动作，走 `article.navigate`；`unit` 由老师在控制台切，**切 `unit` 不重发 `pageMap`**；
- 「整章一屏」（`pageCount > 1` 时出现；名字里的「章」指**当前这一章**，与上一条的「节」不是一对概念）＝**三档顺序**（V2.1.14 定稿；字号是「远处看清」的底线，**最后才动**）：
  ① **先降行距**——`lineHeight` 逐档 −0.05、下限 **1.2**，每档重排判 `pageCount`；到 1 屏即停；
  ② **再抬每行字数**——`charsPerLine` 一步抬到 `cplMax = min(24, floor(availW ÷ fontSizePx))`（不逐档），重排判屏数；到 1 屏即停；
  ③ **最后降字号**——`fontSizePx` 按步长 4 下调、**下限 24**，每档重排判屏数；
  三档走完仍 `pageCount > 1` ⇒ **行距／每行字数／字号三者全部回滚**到点击前的值，并如实回报「整章一屏未达成，仍 N 屏」——**不许留半套参数**。**默认一个参数都不动**，只有点了才进入本流程；控制台始终显示实际生效的三参数（不是请求值）；
- 切场景 → 存 `scrollTop`/锚点，**不 clear**；`article.clear` 才回 `idle`；
- **没有** `autoPlay / speed / volume`；误下发则忽略 + warn，不弹窗。

#### 7.5.1 分页与步进算法（V2.1.10：算术主线；V2.1.6/2.1.7 的几何递推降为校验）

Jeremyzh 11:47 用诗篇 23（和合本 **6 节**——11:47 原话写「7 节」是笔误，已核 `VERSES[23]` 为 6 条）给了精确例子。**下面这张表是他当时的目测示意（每节 2 行、视口 5 行），只用来解释「按节步进会重叠」；真实几何见 §7.5.1 的算例（1080p/72px/`c=12` 首屏 4 行、逐屏 4/5/6）**，**`unit=section` 既不是分页、也不是章内分屏，是「视口按节步进」**：

| 屏 | 内容 |
|----|------|
| 第 1 屏 | 节 1 两行 + 节 2 两行 + 节 3 第 1 行 |
| 点「下一节」→ 第 2 屏 | 节 2 两行 + 节 3 两行 + 节 4 第 1 行 |
| 再点 → 第 3 屏 | 节 3 两行 + 节 4 两行 + 节 5 第 1 行 |

每次把**视口起点移到下一节首行**、屏高不变（一屏容纳几行由字号与段距实测得出，不是算出来的常数）、**允许底部露出半节**。相邻屏必然重叠（本例 3 行）——**这是预期，不是重复渲染的 bug**；验收按此判定，不要去「修」重叠。

**算法（V2.1.10：确定性算术是主路径，DOM 实测降为校验）**

V2.1.7 是「整章渲染 → 逐行读真实几何 → 页起点递推」。Jeremyzh 12:22 要「每行字数可控 → 总行数、节首行号可算」，而**自然折行不可算**（中英数混排宽度不同，同一句话在不同 fallback 字体下行数不同），所以主路径改成算术：

1. **切行（不依赖浏览器折行）**：每节按字符宽度模型切行——全角计 1、半角计 0.5，`L[k] = ceil(节字数 ÷ charsPerLine)`；切出的每一行渲染成一个 `white-space:nowrap` 块，**行数 = 数组长度**。不许让浏览器自然折行后再数行：画出来的行与行号一旦对不上，节首行号、页边界、`viewLines` 全部连带错。
2. **派生值**：`totalLines = ΣL[k]`；`verseLineStart[k]` = `L` 的前缀和；`lineY[i] = Σ_{k<i}(L[k]×行高 + 段距) + (节内行序)×行高`；行高 = `fontSizePx × lineHeight`，段距恒 `1.1em`（=`1.1 × fontSizePx`，`lineHeight` 不改它）。
3. **装页：整节下移（唯一规则）**：从第 1 节起，能整节装进当前屏就装（`Σ L×行高 + (节数−1)×段距 ≤ H`），装不下就开新屏。**不许「填满优先」**——把自身不到一屏的节切开去填满当屏，会让屏数随实现者变（诗篇 23、`c=8`：整节下移 **5 屏**、填满优先 4 屏）。`H = .body.clientHeight`。
4. **某节自身超一屏** → 节内分屏，页脚标「（续）」、下屏「（续上）」，**正文不插任何字符**（字符偏移仍是原文下标）。
5. **输出**：`pageCount` = 装页序列长度；`viewLines` = **首屏**完整行数；`unit=page` 起点 = `pageStarts[pageIndex]`，`unit=section` 起点 = `verseLineStart[sectionIndex]`。两者只由 `(fontSizePx, lineHeight, charsPerLine, H, W)` 决定——同一组输入必须得到同一组输出（可复现，见验收）。
6. **校验（不是主路径）**：渲染后取 `offsetTop/offsetHeight` 与算术值比对，误差 >1px 即**模型错＝bug**：告警并回报（`mqtt.md` §4.6.2），**不得静默按实测覆盖**——否则同一参数会得出两种屏数，验收无从判。

**算例（诗篇 23，147 字、6 节；72px / 行距 1.75 / **H=902（实测）** / 段距 1.1em）**——这张表由上面 6 步算出，验收按它逐格对：

| `charsPerLine` | 每节行数 | `totalLines` | `pageCount` | 首屏 |
|---|---|---|---|---|
| 8 | 2/3/3/4/4/4 | 20 | 5 | 5 |
| 10 | 2/3/3/3/4/4 | 19 | 4 | 5 |
| 12（手动档；V2.1.10 曾为默认） | 2/2/2/3/3/3 | 15 | 3 | 4 |
| 14 | 2/2/2/2/3/3 | 14 | 3 | 4 |
| 16 | 1/2/2/2/2/2 | 11 | 3 | 5 |
| **24（`auto` 在 1080p 的派生值＝现默认）** | 1/1/1/2/2/2 | **9** | **2** | **5** |

**现默认是末行，不是 12**：`charsPerLine="auto"` 在 1080p（W=1728、72px）派生 `c=24` → 9 行、2 屏、首屏 5 行；`12` 只在老师手动锁定时生效（V2.1.10 的默认档，V2.1.11 起降为手动档）。

`c=12` 时 15 行、3 屏，逐屏 **4/5/6 行**——不是「每屏 5 行」：15÷3＝5 只是平均，`viewLines` 报的是首屏 4 行。

**定位实现**：整章 DOM 常驻（行已按第 1 步切好，每行一个块），外层 `overflow:hidden`，内层 `transform: translateY(-lineY[startLine])`。`lineY[]` 现在是**算出来的**，与 CSS 的行高/段距同源，不存在「行号×行高换算」的舍入误差；`Verse 索引`只用于显示，不参与定位。段距只存在于一处 CSS（`.body p{margin:0 0 1.1em}`）——**原型 V2.1.5 的裁行 bug 正来自「平行 ruler」**：ruler 里写 `margin:0 0 .9em`、正文写 `1.1em`，且 `getBoundingClientRect()` **不含 margin**，累加里根本没有段距（72px 下 3 个两行节测得 756≤902 通过，实渲染 756+3×79.2＝993.6，被 `overflow:hidden` 静默裁掉最后一行）。**禁止再维护平行测量层**。

**计数的分母定死（V2.1.7，develop 提、Chief 转达，我采）**：`pageCount` ＝ **整章按 `page` 视口的屏数**，`sectionCount` ＝ **整章节数**；两个数**都恒报、与当前 `unit` 无关**。`unit` 只决定两件事：步进方式（前进 N 行 / 跳到相邻节首行）与 UI 显示哪一个（`page` 显示「3/12」，`section` 显示「节 3/6」，**不显示「3/12」**）。这样切 `unit` 页码不跳数、也不需要重发 `pageMap`。

> V2.1.6 写的「`pageCount` 按当前 `unit` 现算」**作废**：若按 unit 现算，切到 `section` 后 `pageCount` 当场等于节数，页码「3/12」会变成「3/6」——与 D-I「页码只用于显示」直接冲突，且老师会以为翻乱了。

**「续」标记只在 `unit=page` 出现**。`unit=section` 每屏都从节首开始，不需要「续」——V2.1.5「章内分屏标续」是 page 模式的补丁，不能当作 section 的语义（Jeremyzh 11:47 已明确否掉），**但也没有取消**：`unit=page` 下超长章仍标「续」。

**缩进口径（V2.1.6 起；V2.1.14 扩到节内折行）**：**每节首行顶格；`charsPerLine` 落地后每节的折行（第 2 行及以后）也是续行，与 `unit=page` 页切后的续行一样加 1 字符悬挂缩进**（`padding-left:1em` + `text-indent:-1em` 只收首行）；页脚保留小字「（续）」/「（续上）」。理由：排版上「顶格＝新的一节」——若只有页切续行缩进而节内折行顶格，学生会在一节之内读出两个起始（例子里「致缺乏。」顶格正是这个毛病）。

> **几何代价（V2.1.14）**：`auto` 四档恰好 `c×F = W`（24×72=1728、24×48=1152、24×96=2304、24×144=3456，**零余量**）。缩进 1 字符若不同时减字数，行宽变 `(c+1)×F`，会被 `overflow:hidden` 裁掉 1 字（与 V2.1.12 修的 131px 裁行同类）。故定：**带悬挂缩进的行（节内折行 + 页切续行）有效字数 ＝ `c−1`**。代价是行数会变——`c=12/14/18/22/24` 不变，**`c=8` 由 20 行变 23 行、`c=16` 由 11 行变 13 行**（诗篇 23 逐档复算，见验收 B9）。**V2.1.15 定稿为单一表**：行数按 `L(k) = 1`（节字数 ≤ `c`）否则 `1 + ceil((节字数 − c) ÷ (c−1))`，验收回归表只留含缩进的一组（`c=8→23 行/5 屏`、`10→19/4`、`12→15/3`、`14→14/3`、`16→13/3`、`24→9/2`），**不再并列「续行不缩排」的第二张表**；六格屏数 5/4/3/3/3/2 与旧表完全相同，只有 `c=8`、`c=16` 的行数变。另两个选项被否的理由见变更单 §4.16（① 不减字数必然被裁 1 字；③ `5vw` 装不下「节号 ~2 字 + 进 1 字」，差一个量级）。
> 这条与 P1「节号吃首行宽度」同源（都是 exact-fit 零余量），但两者可分开落：本节只管续行；节号已由 Jeremyzh 裁「悬挂」（§7.5.3 落地、四档表一格不动），与本节的续行缩进互不影响。

**`pageMap` 形状（两处并存，不要混）**

- **计算结构**（display 内存，**不落库**）：`{anchor, totalLines, viewLines, verseLineIndex:[…], verseLineStart:[…], pageStarts:[…]}`（后三个都是算出来的，`verseLineStart=` 节首行号）。**不存屏数组**——屏是 `unit` 的函数，预存会在切 `unit` / 改字号后过期。
- **上报摘要**（`state.report.pageMap`，5s 一条）：**7 字段（6 标量 + `viewLines`）** `{anchor, unit, pageIndex, pageCount, sectionIndex, sectionCount, viewLines}`。**`pageCount`（整章 page 模式屏数）与 `sectionCount`（整章节数）恒报、不随 `unit` 变**；`pageIndex` 是当前 `unit` 下的序号，`sectionIndex` 恒报当前节号（`unit=page` 时**也要报**，否则控制台切到「按节」后没有节号可显示）。**不传每屏的 `{startVerseSn,endVerseSn,contStart}` 数组**：那是整张表，5s 全量重传会打爆单连接，且改字号即过期。另报 `viewLines`＝**首屏完整行数**（`pageStarts[0]` 那一屏，语义由开发在 `mqtt.md` V2.2.6 定为「首屏」），供控制台旁注「**首屏** N 行」——**不是每屏行数、不是平均行数**（逐屏可能是 4/5/6），写「行/屏」会让老师以为每屏都这么多；控制台自己按公式算会给错数（见变更单 §4.9）。
- 变更单 §4.4 旧表里的 `pageMap = [{start:{verseSn,charOffset}, …}]`、以及「上报只含 `anchor/pageIndex/pageCount`」两处**均已作废**（字符偏移二分已被行流步进取代）。


### 7.5.2 行距是用户可调项（V2.1.9）

Jeremyzh 12:13：「我需要文章的行数是可以控制的，所以行间距也是人为选择」。**不需要新协议字段**——`lineHeight` 早在 `display.style` 里（`--cds-line-height`，控制台 1.2–2.2、步长 0.05）。缺的是可发现性，因此：

- 字号与行距两个滑块**常驻阅读场景**（不再只在折叠的「显示样式」里），改一次即下发 `display.style`，显示端 `requestAnimationFrame(render)` 重排；
- **样式一变必须重排并重发 `pageMap`**（`mqtt.md` §4.6 的同一条约束）：行高变了，页容量与屏数一起变，不重发就会让控制台的「第 3/12 屏」停留在旧几何上；尾部行数也因此必须重新实测，不能沿用上一次的 `viewLines`；
- **一屏几行只认 display 上报的 `pageMap.viewLines`**。控制台不得自算：固定常数 ≠ `.body.clientHeight`（实测 902；V2.1.14 起不再有第二套 `H`），且公式不含段距（0.63 行/节），72px 会算出 7 行而实测 5 行；行距可调后，任何本地公式在下次拖动后立刻过期。未回报时显示「—（等显示端回报）」；
- **一屏几行 = 字号 × 行距 × 每行字数**三者共同的结果，**不是一个数**：默认 `auto` 下 72px（`c=24`）行距 1.2 / 1.75 / 2.2 → 首屏 **5 / 5 / 3** 行（全章 2/2/3 屏）；手动锁 `c=12` 时 → **6 / 4 / 4** 行（3/3/4 屏）。参考值一律以 §7.5.3 的算法在诗篇 23 上算出，不接受「约 N 行/屏」这类平均口径。

### 7.5.3 每行字数 `charsPerLine` 与两个派生默认值（V2.1.10 / V2.1.11）

原话（Jeremyzh 12:22）：「每一行展示的文字和字符个数也可以控制」「你可以计算出这一篇文章总共有多少行，然后每一节的标识，其实它原文就是一节一行这样提供的」。后半句已由数据满足：`verses(book_id, chapter_sn, verse_sn, verse_txt)` 一节一行（`0001_init_core.sql` L94–100 + UNIQUE），**无需改表**。

**两个控制项都是「自动优先」，默认值不是死数字**（Jeremyzh 12:36 定：投屏可能是 1080p / 2K / 4K，「需要能根据当前字号的大小来调整每行显示多少个字」）：

| 参数 | 默认（派生） | 手动档 | 派生式 |
|---|---|---|---|
| `fontSizePx` | 按屏高派生 | 24–160、步长 4 | `round4(屏高 × 6.7%)` ⇒ 720p **48** / 1080p **72** / 1440p **96** / 2160p **144** |
| `charsPerLine` | `"auto"` | 6–24、步长 1 | `N = clamp(6, 24, floor(W ÷ fontSizePx))`，**`W` ＝ 正文块内容宽**（`.body.clientWidth − 左右 padding`，见下条坑） |

- **三档自洽**：1728/72＝24、2304/96＝24、3456/144＝24 —— 同一份经文在 1080p / 2K / 4K 上得到**同一份分页**（见下表）。固定 12 在 1080p 只用掉可用宽的 50%，到 2K/4K 更窄，等于「4K 上字只有一半大」。
- **144px 是几何必然，不是观感选择（V2.1.14 写死）**：4K 下 `W＝3456`、`c` 上限 24 ⇒ 满行必须 `F＝3456÷24＝**144**`。若 UI 上限只到 120，块宽 `24×120＝2880` 只占可用宽 **83.3%**，两侧各留 **288px** 空白——「4K 上块宽填不满」是几何后果，不是审美分歧。所以 **UI 量程必须能选到 144**（160 是余量档），降回 120 等于每边让出 288px。
- **24 是可读性底线，不是技术上限**：24px 字号下 `floor(1728/24)=72`、48px 时 36——屏上装得下，但**一行超过 24 个全角字，后排跟行会跳字**。协议字段（`mqtt.md` V2.2.10）容错接受 6–40，25–40 到达显示端一律按能用的上限收紧并在 `ack.effective` 回带；**产品 UI 量程就是 6–24**，下一轮不得以「屏幕装得下」为理由放开成 72。
- **硬约束（联动 clamp）**：`charsPerLine × fontSizePx ≤ 可用宽`；1920 宽扣 5vw×2 = **1728px** ⇒ 上限随字号降：72px→24、96px→18、120px→14、144px→12、160px→10。字号拨大时滑块 `max` 当场降、当前值 clamp 到新上限，旁边显示「上限 N 字」——**不许让字跑出屏幕，也不许静默改值**（生效值以 `ack.effective` 为准）。
- **`W` 必须是正文块的「内容宽」（V2.1.12 实测坑）**：`W = .body.clientWidth − 左右 padding`，**不能拿 `#content.clientWidth`**——它含 5vw 左右 padding，1280 屏会读到 **1280**（真可用 **1152**），每行多排 2 字，行宽 `24×52=1248 > 1152`，`overflow:hidden` 下行尾被**静默裁掉**（原型实测溢出 131px，肉眼只看到半行）。渲染期 `.body` 尚未插入时用 `0.9 × innerWidth`。同理，控制台的「每行上限」要按显示端回报的 `state.report.layout.availW`（与同一条 `layout.fontSizePx`）算，不得本机自算、也不得写死 1728。**`layout` 的下达有两条路（V2.1.22 更新；V2.1.18 写的「`api.md` 14,048 B、`layout` 0 命中」已过时）**：① MQTT 上行 `state.report`（`retain=true`）；② REST `GET /devices/{id}/state`——`api.md` 自 V2.2.2 起 **19,827 B**，§4.5 已补响应体，`layout` 五项与 `state.report.layout` **同名同形**。两条路必须**同源**：断 MQTT 后 2s 轮询、恢复即停（并存会出两个页号）。
- **派生值给老师看**：`totalLines`（全篇行数）、`verseLineStart[k]`（每节首行号）、`pageCount`（屏数）。显示端页眉「第 1 / 2 屏 · 全篇 9 行」；控制台「每行 24 字 · 首屏 5 行 · 共 2 屏」。**`totalLines`/`verseLineStart` 不上行**（`pageMap` 恒 7 字段，不含 `charsPerLine`），控制台只读 `pageCount`/`viewLines`，其余不得自算。
- **切行不靠浏览器**：全角 1／半角 0.5 累加切行，每行一个 `nowrap` 块，`L[k]=ceil(节字数 ÷ c)` 是行数的唯一来源。自然折行会让行数随字体 fallback 漂移，节首行号与页边界一起错。

**跨屏一致性（V2.1.11 红线——A 方案唯一可证伪的断言）**：诗篇 23（16/21/21/25/32/32＝147 字、整节下移、行距 1.75、段距 1.1em）

| 屏 | `fontSizePx` | 可用宽 `W` | `H`（`.body.clientHeight` 实测） | `H÷F` | `auto` 派生 `c` | 每节行数 | `totalLines` | `pageCount` | 逐屏 |
|---|---|---|---|---|---|---|---|---|---|
| 720p | 48 | 1152 | **587** | 12.23 | 24 | 1/1/1/2/2/2 | 9 | 2 | 5/4 |
| 1080p | 72 | 1728 | **902** | 12.53 | 24 | 1/1/1/2/2/2 | 9 | 2 | 5/4 |
| 2K | 96 | 2304 | **1217** | 12.68 | 24 | 1/1/1/2/2/2 | 9 | 2 | 5/4 |
| 4K | 144 | 3456 | **1847** | 12.83 | 24 | 1/1/1/2/2/2 | 9 | 2 | 5/4 |

四档输入给**同一份分页**：第 1 屏＝节 1–4（5 行），第 2 屏＝节 5–6（4 行）。**边界要写清**：`auto` 只保证每行字数与屏宽同比例（行数序列一致）；**屏数**还取决于 `H ÷ fontSizePx`，而 `H` 含不随屏缩放的页眉页脚。

**`H` 只有一套：原型实测**（V2.1.12 起定，V2.1.14 单一化）：720p **587**、1080p **902**、1440p **1217**、4K **1847**（`.body.clientHeight`，含 5vh×2 外边距与页眉页脚；1080p 是整块高 972 减页眉页脚 **70px** 得 902——**不是 61px**）。四档 `H÷F` ＝ **12.23 / 12.53 / 12.68 / 12.83**，都在 `12.05 ≤ H÷F < 16.65` 内，所以同屏数。
> **旧的「模型列」已删（V2.1.14）**：本表原有一列 `H` ＝ 608/911/1296/1944（「屏高×0.9 − 61px」，`mqtt.md` V2.2.10 的估算）。删它不只是因为口径作废，而是因为 **1296÷96 ＝ 13.5、1944÷144 ＝ 13.5**——留着这一列，`H÷F` 就还能算出 13.5，作废值会从这里复活，下一轮照 13.5 反推页眉高度会得 0 或负数。`mqtt.md` §4.6.3（V2.2.15）已改用同一组实测值，**不再有第二套 H**。
> **13.5 已作废**：那是「屏高×0.9、不减页眉」算出来的。按 13.5 反推会得到「页眉页脚挤出 0px 甚至负数」，下一轮照它算就错。V2.1.11 写的 12.86 / 13.08 是「屏高×0.9 − 61px」的口径，也以本节实测值为准。**反例**：页眉页脚绝对高变大（1080p 下 `H` 跌到 867.6 以下）时 1080p 的 `H÷F` 跌破 12.05 → 分页变 3/4/2，而 4K 仍 2 屏 ⇒ **分叉**。验收只钉这四组输入，不写「任何屏都一致」。

**原型实测回填（V2.1.12，Chromium 按窗口尺寸逐档量，可复现）**：

| 窗口 CSS px | `clientWidth` | `clientHeight` | 派生字号 | `auto` → `c` | `totalLines` | `pageCount` | 逐屏 |
|---|---|---|---|---|---|---|---|
| 1280×720 | 1152 | 587 | 48 | 24 | 9 | 2 | 5/4 |
| 1920×1080 | 1728 | 902 | 72 | 24 | 9 | 2 | 5/4 |
| 2560×1440 | 2304 | 1217 | 96 | 24 | 9 | 2 | 5/4 |
| 3840×2160 | 3456 | 1847 | 144 | 24 | 9 | 2 | 5/4 |
| 1280×800（4:3 之外的常见窗口） | 1152 | 657 | 52 | 22 | 9 | 2 | 5/4 |
| 1640×1080（Jeremyzh 12:45 提到的窄宽） | 1476 | 902 | 72 | **20** | **11** | **3** | 5/4/2 |

**最后一行是反例，必须留着**：1640 宽下 `floor(1476/72)=20`，每节第二行多切一刀 → 11 行 3 屏。这说明「24 字/行」不是万能常数，而是 `W÷F` 恰好等于 24 的四档才有的结果；**验收不得把 1640 也写成 9 行 2 屏**。

- **4K 电视的坑**：大量 4K 电视以 **DPR=2 报 1920×1080 CSS px**，此时行为与 1080p 完全一致（72px、`c=24`、首屏 5 行），**不要按营销分辨率判**。判定一律用 CSS px viewport；只有 viewport 真报 3840 宽才用 144px/24 字。**派生输入口径定死＝视口高（CSS px）**，不是物理屏高、也不是营销分辨率——窗口化预览时两者不同，按物理屏高会给出另一套分页（`mqtt.md` V2.2.12 ⑤ 待产品确认项，此处答复）。
- **已知缺口（P1，验收不判）**：按宽度硬切、**未做避头尾**（「。」可能落行首）；半角一律 0.5（`Li 3:16` 的字母数字空格同权）；显式锁小（如 12）时行宽 `c×F` 只占可用宽一半，**块宽建议＝`c × fontSizePx` 居中**（`auto` 下自然满行），待 Jeremyzh 看原型定。
- **行首元素（节号）悬挂——已裁决并落地（V2.1.26，Jeremyzh 20:11 选「悬挂」）**：`27px@1280×800 / 49px@1920 / 98px@4K` 的首行裁行由 `.sn` 出框解决，**四档表一格不动**（`usableW` 逐像素不变）。三处细节是实测踩出来的，照抄即可：
  1. `.body{padding-left:1em;margin-left:-1em}`：`padding-left` 给节号让位、负 margin 抵回，内容宽不变；`overflow:hidden` 裁的是 **padding box**，节号落在 padding 区内不会被裁。
  2. **`.sn` 必须移出 `.ln`**：`.ln` 自己是 `overflow:hidden`（就是静默裁行那一层），`position:absolute;right:100%` 挂在 `.ln` 里面会被 `.ln` 自己裁掉。
  3. **`.flow` 要写 `left:1em`**：绝对定位子元素的 `left:0` 参照的是 **padding box** 而不是 content box，不写 1em 时 `.flow` 会盖住 `.body` 的 padding 区，节号照样被裁（我第一版就踩在这里，截图可见被裁）。
  - 对外数字只用一种口径：**「槽宽 − 节号字形宽」= 25 / 23 / 46 px**（1em 槽＝52/72/144，节号字形宽＝27/49/98）。此前写过的「余量 17px」是把 `.sn` 的 `margin-right:.5em`（按 `.sn` 自身 0.6em 字号换算）也算进去的旧口径；悬挂实现下 `.sn` 出框、`margin-right` 归零，间距由 5vw 槽的剩余量给，**不得再引用 17**。
- **本场景任一字段变化 → 重排**（V2.1.34 扩）：`article` 的三参、`music` 的 `lyricFontSizePx`（一页歌词行数 `N` 随之变）、`cast` 的 `fontSizePx`。有分页的场景重发 `pageMap`；`cast`/歌词无分页时**不得上报上一场景的旧 `pageMap`**（`mqtt.md` V2.2.27 ⑨）。旧 `pageCount`/`viewLines` 立即作废，不得跨样式复用。
- **生效值只走 `ack`（V2.1.34：按场景给键）**：`article` 三值 `{fontSizePx, lineHeight, charsPerLine}`（`auto` 回派生整数）；`music` 三值 `{fontSizePx, lineHeight, lyricFontSizePx}`；`cast` 两值 `{fontSizePx, lineHeight}`（`charsPerLine` 对板书无意义 ⇒ 省略，不回 `null`）；`standby` `{}`（不得编造数值）。`ack.payload` 回带 `scene`，控制台据此写回对应面板。**几何不回 `ack`**——`availW`/`availH` 走 `state.report.layout`（每次重排后上报、**200ms 防抖**、`retain` 下新控制台即刻拿到；V2.2.15 撤销了「`effective` 增 `availW`/`availH`」，理由是同一事实写两处必然打架）。`pageMap` 恒 7 字段。
- **控制台的每行上限必须用同一帧的 `layout`**：`c_max = min(24, floor(layout.availW ÷ layout.fontSizePx))`，两项**取自同一次上报**；**`W` 不得写死 1728**（1280 屏可用宽是 1152）。从未收到 `layout` 时才回退 1728，并标注「估算」。

### 7.6 板书 `castStore`

`idle → draft → previewing → casting → ending → idle`，任意态 `error` 回 `draft`。

- `text` 直接 `POST /cast/start`；`image/pdf` 先 `presign` 上传再 `cast.start(contentUrl)`；
- **V2.1.9 触屏替代**：`pointer:coarse` 下**不绑双击**（双击＝缩放/选词、长按＝选词，都不能当发送），改用**固定「发送」按钮**（拇指区、≥44px，`pointer:coarse,(max-width:900px)` 下占满一行 ≥52px 高）；桌面仍双击发送。控制端可以是手机，但**手机不放声**（声音只从接场地音响的电脑出，D-A′），音乐面板置灰并写明原因；
- **V2.1.5 发送语义**：编辑区是**满高**（占面板剩余高度，约 80%），**双击即发送「光标所在行及其上方共 N 行」**（N 可选 3/5/8/10/全部，默认 5；不足 N 行取到首行；尾部空行 trim）；`dblclick` 要 `preventDefault`，并把选区收成光标（`preventDefault` 本身**不阻止**双击选词）；发送后 **3 秒撤销** toast；
- **草稿与已上屏必须是两个字段**：`cast.draft`（编辑区内容，随输入保存）与 `cast.text`（显示端正在显示的内容）。合成一个字段会在每次发送后把老师写好的整篇草稿替换成刚发出去的那几行（原型实测踩到）；
- 已投屏时再双击＝**同 `castId` 重发**，显示端原地替换 `.paper` 文本、不重建 DOM（不闪）；`cast.end` 用**已上屏**的 `text`，不用草稿；
- **`fullScreen` 字段不再下发**（V2.0 板书独占全屏）；
- `cast.end` 回 `idle` 场景（不是回上一场景——互斥下"结束板书"= 回到 Idle，由老师再选）；
- `ack 4004`/`4093` → 重新预签名 ≤2 次，仍失败 → toast + 回 `draft`。

### 7.8 样式 `styleStore`（V2.0 新增）

`default → editing → pushing → applied | failed`

- 值为受控枚举（字体从白名单选，不开放任意输入，防注入）；
- `pushing` 时按钮转圈；`ack` 后 `applied`，`styleVersion++`；
- 3s 无 `ack` → `failed`，提示"样式可能未生效，屏幕需在线"，保留待推值，恢复连接后自动重推；
- 显示端 `state.report.styleVersion` 与本地不一致 → 控制台自动重推一次。

| `cast.start` / `cast.end` | `CastScene` | 同 `castId` 不重渲染；`cast.end` 未在投屏态 → `ack ok` |
| **`display.style`** | 全局变量 | 同 `styleVersion` 不重写变量 |
| **`device.bindState`** | 全局（每台屏一条 `d/{deviceId}/bind`，retain=true） | **状态快照，不是事件**。`state ∈ {bound, revoked}`；`reason ∈ {code_rotated, kicked, unbind}`（V2.1.38 改拼写：`unbound` 只是 `state` 取值之一，不是 `reason`） 只决定文案、**不得当事件触发器**。**retained 只负责即时性；有效性以 DB／REST 自检为准**（`mqtt.md` V2.2.24 §6-2）：启动时先凭设备凭据自检 `GET /devices/me` 的 `state`（`api.md` §4.6，`unbound` ＝ 从未绑定），**快照缺失不得判「从未绑定」**（retained 会 TTL 过期／丢失／发错主题，按缺失判会把合法在用的屏误踢回输码页）；缺失或不符时以 REST 对齐、由服务端补写，REST 不可用不得凭快照清凭据。解绑用空 payload 清、不造 `unbound` 三态。处理：与本地状态**相同则无操作**（幂等）；`revoked` ⇒ 清 `userId`/凭据/`boundAt`、退订 `u/{userId}/cmd`、停上报、**不得**清自己那两条 retained（V2.2.24 改为**服务端**在同一事务内向 `state`/`presence` 各发空 payload——被踢端可能已离线或是恶意端，自己擦痕迹等于不擦；显示端回写会把痕迹又写回去）、**先回 `standby`** 再回输码页。**为什么必须快照**：retained 一次性撤销不会因被消费而消失，被踢的屏重绑成功后订阅瞬间又收到、再被踢（刷新→重绑→再踢的死循环）。**最晚时点＝重连后订阅到达时**（retained 保证订阅那一刻拿到当前值）。~~`code.revoked`／`code.issued`~~ **从未进入本协议**（V2.2.23 明示），整对作废 |
| `device.ping` / `device.reload` | `SystemLayer` / 全局 | `pong`；先 `ack` 再 `reload`（延迟 200ms） |

### 8.3 进度插值（控制台）

同 V1.0：`state.report` 每 5s；`shown = pos + (now - at) * isPlaying`，`min(durationMs)`；暂停不插值；拖动不插值；差值 <1500ms 视为已对齐。

> **（V2.1.8）这里的 1500ms 是「控制台进度条」对显示端上报值的容忍，不是时基纠漂**。时基纠漂走下行 `player.sync`、三档死区 80/300ms（§10.6 第 3 条），两者**不得互相借用阈值**——一个管 UI 数字要不要跳，一个管歌词要不要重锚，量级差一个数量级。

### 8.4 一用户多屏：哪些是「逐屏」的、哪些共用（CO-2026-11-18-05）

> 本节回答 Chief 20:11 的问题①：一个用户一张码、一个控制端控 N 台屏之后，`scene` / `nowPlaying` 是否强制同场景。

| 事实 | 逐屏还是共用 | 后果 |
|------|--------------|------|
| `scene`、`viewing`、`casting`、`nowPlaying`、`audio.playing` | **逐屏** | 各屏可以各自不同场景。`state` 里它们本来就是每屏一份，改成共用要新增一条"户级场景"事实——两份事实必然打架 |
| `pageIndex` / `pageCount` / `viewLines` | **逐屏，且必然不同** | 同一节 1280 是 22 字/行、1920 是 24 字/行，页数不同；分辨率不同时"让全班停在同一页"物理上做不到 |
| 控制码 | **共用**（一用户一张） | 管的是「谁能控制」，不是「显示什么」 |
| 下行 `cmd` | 主题可共用，但**每条必须带 `target`** | 见下 |

**结论：不强制同场景，`scene`/`nowPlaying` 一律逐屏。** 三条理由：① 分辨率差异已经让 `pageIndex` 无法共享，强制同场景也换不来"同页"；② 一台屏换教室 / 检修 / 临时黑屏时，强制同步会拖死其余屏；③ 1280×800 与 4K 混布是既定事实（§7.5.3 四档表）。**所以"一个控制端控多屏"成立，但"多屏同一状态"不成立**——控制台要提供屏选择器，默认作用于选中那台。

**`target` 规则（硬约束）**
- 每条下行命令必须带 `target`：`{deviceId}` 或 `'all'`。**缺 `target` ＝ 拒绝（`ack 4001`），不得默认广播**——静默广播的爆炸半径是整个班的屏。
- "全部屏幕"必须是显式动作，且默认不是它。
- `cast.start` **不得** `target:'all'`：`contentUrl` 按设备预签名（`api.md` §4.3），一次签发只对一台有效；要对全班投同一份，控制台逐屏签发。
- 页码类命令（若将来出现）**不得** `target:'all'`：各屏页数不同，语义不确定。

**主题结构（CO-05 定的用户级隔离，我认同，并补一条我坚持的）**

```
cds/v1/u/{userId}/cmd                 服务端/控制端 → 同户全部屏  账户级指令（`to` 定向） QoS1, retain=false
cds/v1/u/{userId}/ack/{deviceId}      显示端 → 服务端             回执                  QoS1, retain=false
cds/v1/u/{userId}/state/{deviceId}    显示端 → 服务端             状态                  QoS1, retain=true
cds/v1/u/{userId}/presence/{deviceId} 显示端 → 服务端             上下线（LWT）         QoS1, retain=true
cds/v1/d/{deviceId}/bind              服务端 → 显示端             绑定状态快照          QoS1, retain=true
```

- `state` / `presence` **必须每屏一条**：两者都是 `retain=true`，共用即后写覆盖——`layout.availW` 随屏而异（1280→1152、1920→1728），共用只能看到最后一台，另一台必踩 §4.6 的静默 clamp（锁 24 被收回 18）；`presence` 靠 LWT 标离线，共用时一台断线即整户判离线，N 从 2 跳到 0。
- **topic 段一律用 `deviceId`（或 `userId` 段），禁止用控制码**：码是口令，进 topic 等于向所有订阅者广播。
- `cmd` **协议侧已定共用一条** `u/{userId}/cmd`（`mqtt.md` V2.2.23），我原先推荐的「每屏一条」没被采纳——**这不影响产品行为**，但把 `to` 变成了硬约束：`to ∈ {"*"} | {deviceId}`，**必填，缺则丢弃（fail-closed）**，非目标屏不执行也不回 `ack`。`device.reload`/`device.restart` 这类单机指令广播会把全户屏一起重启，必须带 `to`。
- `bind` 放**设备命名空间** `d/{deviceId}/bind` 而不是用户命名空间：显示端未绑定时尚不知道 `userId`，放用户树会形成鸡生蛋。**LWT 必须在 CONNECT 时算得出** ⇒ 启动顺序定死：先凭设备凭据取 `userId` → 注册 LWT → 订阅 `bind` 快照 → 已绑定才订阅 `cmd`。

## 9. 显示端渲染模型（互斥版）

### 9.0 两条物理约束（写给现场，不做成功能）

1. **显控一体 = HDMI 复制**：投影上是老师屏幕的逐像素副本，**包括迷你控制条、包括点"黑屏"的那一下**。所以"学生看不到我的操作"在这个形态下做不到；做到的是"内容不泄露"（`blank`）与"控制条尽量小、可淡出"。**「黑屏」的真实作用是「不让学生看到下一条内容」**（老师在本机准备下一篇经文时先黑屏），**不是防窥**——不要对外承诺"学生看不出老师在操作"。
2. **复制模式下无法同时显示 PPT 或其他软件**。三条出路：① 把 PPT 导出 PDF 走板书场景（推荐，最稳）；② PPT 窗口化（学生仍看到整个桌面，效果差）；③ 换扩展模式 + 手机控制（= 多屏模式，此时音乐按 D-A′ 前置条件降级）。**不对外承诺"一边放 PPT 一边控制"。**


### 9.1 图层（简化）

```
L2 SystemLayer   断线 / 重连 / 码失效                     z-50  非阻塞、半透明
                 （V2.1.1：display 不认识音频，音频锚点冲突提示只在控制页）
L1 ContentLayer  按 scene 只显示一个：Standby | Music | Article | Cast   z-10
   （V2.1：没有 <audio> 了，图层里不再有"常驻挂载的音频持有者"）
L0 无            待机不是"空"，是 L1 里的 StandbyScene（主题图或纯黑）
```

- **视觉上**只有当前 scene 可见（`display:none` + `aria-hidden`）。声音与画面解耦，但**解耦 ≠ 自由**（V2.1.2）：`music`→`standby` 音乐继续播；`music`→`article|cast` 由**编排**先 `player.pause` 再切画面（Jeremyzh「板书时不要放配乐」）；切回 `music` 按 `positionMs` 重锚。display 上没有 `<audio>` 可管——声音在控制页，由 `cds.audio.lease` 的持有者播，display 不知道音乐状态。
- 这不是 D-04 的"并存"：D-04 是同一台设备两个流程叠图层、两块内容同时可见；这里同一时刻只有一块内容可见，另一维度是**另一台设备上的声音**。
- 不使用多层透明叠加、不使用 `position:absolute` 堆全部场景（避免命中测试与无障碍污染）：非当前 scene `display:none` + `aria-hidden="true"`，`<audio>` 用 `<div hidden>` 包住但不卸载 React 树。

### 9.2 互斥不变量（code review 必查）

1. `scene.set(music→article|cast)` 指令本身**不隐式** `audio.pause()`（保住 `mqtt.md`「`cast.*` / `article.*` 无 `player.*` 副作用」）；暂停由**控制服务编排**在同一次用户动作里先发 `player.pause`、收到 `ack` 再发 `scene.set`/`cast.start`（`ack` 1.5s 未到**仍切画面**，控制台标「音乐未确认停止」+ 停止键）。`scene` 与 `audio` 是两个字段：仲裁器**不得**因切画面把 `audio` 置 `none`，也**不得**让 `scene ∈ {article,cast}` 时 `audio.playing=true`——该状态下收到 `player.play|resume` 一律 **MQTT `ack 4009`**（REST 侧 `4096` + HTTP 409）`audio_blocked_by_scene`（第二道闸，防客户端绕过编排）。
2. `scene.set(article|cast)→music` 时，歌词必须按控制页当前 `positionMs` **重锚**（不是从 0，也不是「续上刚才那帧」）；音频本身全程未停，不做 `play()` 第二次调用。
3. `article.clear` / `cast.end` 不得触发 `player.stop`，**也不得自动 `resume`**（回 `standby`，等老师再点继续/点"音乐"Tab）。
4. `cast.*` 处理器内无 `audio.*` 调用。
5. 三场景 DOM 不 teardown（切回不重新拉接口、不回到章首/曲首）。

## 10. 异常与降级

### 10.1 指令未确认
`ack` 3s 未回 → 同 `msgId` 重发 1 次 → 再 3s → toast「指令未确认」+ UI 回落到最近 `state.report`。

### 10.2 MQTT 不可用
`degraded`：顶部黄条「实时通道断开，正在用轮询同步（可能有 2s 延迟）」；指令照常可点，`delivered:"polling"` 时按钮旁黄点。

### 10.3 终端离线
N=0：所有控制按钮 `disabled` + 「教室屏幕未连接」；恢复后以 `state.report`（retain）全量对齐。

### 10.4 多终端部分在线
计数显示 `2/3 在线`（分母=已绑定上限内数量）；控制照常下发（fanout），以**最慢 ack** 作为"已生效"判据；超时只提示不阻断。

### 10.5 板书 URL 过期（4093 / ack 4004）
自动重签 → 重发 `cast.start`（新 `msgId`、同 `castId`）；两次失败 → "板书素材加载失败，请重新选择"。

### 10.6 音频锚点与手势（V2.1 全节重写）

> **本节不是分页。** 分页与 `unit=page|section` 的步进语义在 **§7.5.1**（V2.1.6）。按旧目录找「分页/翻页」会撞到这里，故留指路——V2.1.5 曾把分页算法要求写在本节，是错的位置。

> V2.0 的「输码手势内建 `AudioContext` → 静音探测 → 绑定」整节**删除**：display 已无音频，自动播放风险类别整体消失（变更单 §3）。同时删除形态 B「按遥控器任意键开始」例外——无音频可解锁。**不要以"暂不启用"的形式保留这段代码**，否则后人会当有效需求实现。

**三条约束（code review 必查）：**

1. **声音只从控制页出**。控制页 = `/#/console` 或 `/#/screen`。display 里出现 `new Audio` / `AudioContext` / `<audio>` → 直接打回。
2. **一首歌只有一个锚点**。`localStorage.cds.audio.lease = {owner, ts}`，owner 每 2s 续期，3s 未续视为过期；抢不到的一侧**静音跟随**，控制条显示「另一窗口正在播放，此处静音」。不做 → 现场是"投了有回声/两轨错位"，最难查的一类。
3. **时基用显示端本地单调时钟**（V2.1.1 修正；原「服务端打点」写法作废）。`player.play` 只带 `positionMs`、`durationMs`，**不带 `startedAtEpochMs`**。display 收到 `play` 时：`t0 = performance.now(); base = positionMs; pos(t) = base + (performance.now() - t0)`，rAF 推进。**（V2.1.8）`delayMs` 不再进时基**——它既不加入 `base`，也不进 `Δ`（见下面两条）；留在代码里只作 UI 诊断。
   - **纠漂源＝下行 `player.sync`（方向 V2.1.7 定、字段 V2.1.8 定稿）**：音频宿主（控制页）发 `player.sync {trackId, seq, positionMs, isPlaying}`，服务端**转发下行**给 display。**发送时机**：每 5s 一条；`connack` 之后、`visibilitychange → visible`、`presence online` 各**补一条**（这三种「刚回来」的状态最容易带着旧值，只靠 5s 节拍要多等最多 5 秒）。
   - **Δ 的算式（V2.1.8）**：`Δ = positionMs − pos(now)`，**不含 `delayMs`**。`positionMs` 是控制页发出那一刻的真实播放位置，`pos(now)` 是显示端此刻认为的位置，两者之差就是显示端要补的量。
   - **`seq` / `trackId` / `isPlaying` 各管一件事**：`seq` 会话内单调递增，display **只接受 `seq > lastSeq`**（重连后的旧包直接丢，否则会拿 5 秒前的值重锚）；`trackId` 变了即判换曲，丢弃旧曲的 sync，避免切歌瞬间被上一个 `positionMs` 拉回去；`isPlaying=false` 时冻结在 `positionMs`，不得继续让歌词爬。
   - **不带 `durationMs`**：display 只画歌词、不画进度条（进度条在控制页），时长对显示端没有使用点——多一个字段就多一处要同步的口径。
   - **不能拿 `state.report` 当纠漂源**：它是 display→服务端的**上行**，display 收不到自己的 report；即便自订阅，也是拿自己刚发的值重锚，`Δ` 恒为 0、零纠偏，还会把上报延迟当成漂移——这正是「5s 重锚」始终没有载体、§13 的 <120ms 指标无法验证的原因。
   - **重锚三档死区（阈值 V2.1.3 定、算式 V2.1.8 定）**：按上式（`Δ = positionMs − pos(now)`，不含 `delayMs`）算出 `Δ` 后，`|Δ| < 80ms` → **忽略**（落在测量噪声内，且每 5s 微跳肉眼可见）；`80ms ≤ |Δ| ≤ 300ms` → **慢追**（每帧向目标靠 10%、单帧 ≤5ms，约 2s 收敛，不跳）；`|Δ| > 300ms` → **直接跳**（`base = positionMs; t0 = performance.now(); lastSeq = seq`）。**这三档是唯一口径**，取代此前文档里的 200ms、250ms 与开发「80/300 死区」三种写法；任何一处引用都指向本节。
   - **`delayMs` 退出时基（V2.1.8 作废）**：原写法是控制页发 `play` 记 `sendT`、收 `ack` 记 `recvT`、单程取 `(recvT − sendT)/2`，再取最近 3 次中位数、clamp ≤300ms 后加进 `base` 与 `Δ`。作废原因两条：① 它量的只是「控制页→服务端」，而真正要补的是「控制页→显示端」**整段**单程，补一半、留一半，`base` 与 `Δ` 用了不同口径，两边符号相反时还会互相抵消（看起来"补了"其实没补）；② 这个量级（教室 Wi-Fi 约 20–80ms）本来就落在 80ms 死区内，再叠加一个带估计噪声的常数，只会把 `Δ` 的基线推偏。**测量代码可以留，仅作 UI 诊断**（如「网络较慢」提示），**不得进入 `pos(t)` / `base` / `Δ`**——review 用 `rg -n 'delayMs' src/display/player/` 必须只命中诊断分支。
   - **为什么不能用 `startedAtEpochMs`**：服务端打点只消掉「控制台↔服务端」钟差，**消不掉「显示端↔服务端」钟差**。`positionMs + (Date.now() - startedAtEpochMs)` 里的 `Date.now()` 是**显示端**的钟——D-1 的电视棒/盒子没有 NTP，钟可差几十秒到几分钟，且随开机/校时跳变，表现是歌词整段跳或一路爬。这条错误不会在开发机上暴露（同机同钟），只在真机出现。
   - **残余误差 ＝ 两段单程之和 `R`（V2.2.11 订正；原文「只剩控制页→显示端整段单程、落在 80ms 死区内」错）**：音频宿主是**控制页**、不是服务端，故 `R ＝「控制页→服务端」＋「服务端→显示端」`（典型 40–100ms）。`positionMs` 是控制页**发出时**的位置，显示端收到时音频已前进 `R`，故 `Δ = positionMs − pos(now) ≈ −(R + e)`，`Δ → 0` 收敛到 `e = −R`，即显示端**稳定落后 `R`**——既不是落后一个单程，也不收敛到 0。**80ms 死区只抑制小于半帧的抖动修正、不吸收残余**：`R ≤ 80` 时完全不纠（滞后 ＝ `R`）；`80 < R ≤ 300` 时慢追停在死区边界，滞后落在 `[R−80, R]` 内（每轮 5s 回到上界）。这是刻意取舍：不引入 `delayMs` 一类**估计量**去补偿（两段单程都不是常数，估计偏差还会把歌词推到音频之前）。**不随运行时间累积**，5s 重锚只防累积漂移、**不缩小 `R`**。要更紧只能上 PTP/NTP，那是另一件事。
   - **时间预算按 `R` 判、不按单程（V2.2.11）**：§13 的「<120ms」是**总预算**，故**装机合格线 ＝ `R ≤ 100ms`**（留 20ms 余量）、**`R > 120ms` 判不可达**、`R` 落在 100–120ms 属**临界**须现场复测后书面确认。早前「单程 ≤80ms 时 <120ms 才成立」**作废**：两段各 80ms ⇒ `R = 160ms`，已超预算；**单程 80ms 只是纠漂阈值（死区半宽带）**，不是预算线。装机预检必须**逐教室实测 `R`**（控制页触发 `seek` 后比对显示端落点时间差，或两端各记 `performance.now()` 相减）并留档备查，不得事后当 bug 查。例：4G 备份链路单程 150ms ⇒ `R ≈ 300ms`，此时只能按「>300ms 跳档」纠偏，**不得承诺 §13 指标**。
   - **页面重载后 `performance.now()` 归零**：不得从旧 `t0` 续算，必须先 `GET /devices/{id}/state` 拿当前 `positionMs` 再重锚（与 §10.9 断网重启同一路径）。
   - **`lines[]` 只在 `trackId` 变化时下发**，不随 5s 回执重传全量 LRC（单连接会被打爆）。

**移动端控制页**：`visibilitychange → hidden` 立即 `pause` 并记位置；回前台**不自动续播**（防教室突然出声），提示「已暂停，点播放继续」。手机/平板默认音乐置灰（见 D-A′ 前置条件）。

**部署前提（写给运维与现场）**：控制页所在设备必须接场地音响——单屏模式走 HDMI 回传、笔记本走线路输出、或蓝牙。这条不在代码里能兜住。

### 10.8 控制码失效 / 被移出接管（V2.1.26 按 CO-05 重写）

- **判定权在服务端，判据是「我这条绑定还有效吗」**：显示端凭 `Device` 凭据请求 `GET /devices/me`（不是凭码），服务端只回 `state ∈ {bound, revoked, unbound}`。**不得**新增按码查状态的接口（见验收 A 区红线），否则等于把码变成可枚举的通道。
- **触发**：`cds/v1/d/{deviceId}/bind` 上的保留快照变为 `state:'revoked'`——**订阅即得**，实时与重连走的是同一条路；`reason` 只决定文案。
- **显示端动作**：清 `cds.bound`/`credential`/`boundAt` → **先回 `standby`**（`article`/`cast` 不得停留：没人能翻页）→ 输码页；提示条常驻，不自动消失。
- **文案按 `reason` 分（V2.1.47 起三句必须互不相同）**：`kicked` →「已被移出接管，请重新输入控制码」；`code_rotated` →「控制码已更新，请重新输入」；`unbind` →「本屏已解除接管，请重新输入控制码」。此前 `code_rotated`/`unbind` 共用一句，与 `api.md` §4.6「三种 `reason` 必须对应三种可区分文案」冲突，已分开。**移出接管是操作手段，不是封禁**——不得出现「禁止接入 / 已封禁」。
- **控制码不得持久化（`api.md` §4.2 硬约束）**：绑定成功后屏端只留 `deviceToken`；`cds.code` 一类码副本**必须删除**（旧版本残留启动即清）。理由：码是**长期有效**口令，留在 `localStorage` 等于把口令贴在教室屏上——学生/清洁工开一次开发者工具就能读走，进而把自己的屏绑进老师账号、占满 4 台上限、看到投屏内容（控制要登录，但「看」不需要）。
- **自检不得按码比对、也不得读本地标记**：原型演示态用「码修订号」`cds.codeRev`（随机串、**不含码**）模拟「控制台换了码」；真机**只认** `GET /devices/me`。`401`（带 `WWW-Authenticate: Device`）只清**设备**凭据回注册，**不得**连带清控制台 JWT。
- **不再有「已过期」这一支**：码长期有效，`expired` / `used` 两个 reason 随 CO-05 一起删除；提交失败只可能是 `invalid`（「控制码无效，请与控制台核对」）或 `rate_limited`（「尝试过于频繁，请 1 分钟后再试」）。
- **控制台**：`GET /devices/list` 归零 + toast「教室屏幕已断开，请确认屏幕上的控制码」。
- 隐藏重置：长按 3 秒（环形进度）/ `?reset=1`——**这是输码态的**「清除本地码」，不是解绑；内容态的右下角长按 3 秒才是解绑（§3.4.1），两者文案与实现都不得混用。

### 10.9 显示端断网重启
有码 + 有 `cds.style` + 有 `cds.lastFrame`：先渲染最后一帧（防黑屏）→ 连上后以 `state.report` 对齐；无网 60s 后系统层提示「网络异常，正在重连」。

## 12. 可用性 / 键盘 / 无障碍

**控制台快捷键**（输入框聚焦时禁用）：`Space` 播放/暂停；`←/→` 文章上一屏/下一屏、音乐 -5s/+5s；`↑/↓` 音量 ±5；`/` 聚焦预选搜索（仅编辑态）；`1/2/3` 切三个场景；`Esc` 关闭弹层。

**无障碍**：对比度 ≥4.5:1（**歌词 ≥24px 属大文本，按 3:1 判**，见 §5.2）；触控目标 ≥44×44px；状态变化 `aria-live="polite"`（含终端计数）；图标按钮有 `aria-label`；状态不只靠颜色（点 + 文案）。

**显示端**：除 `CodeEntry` 外无交互元素；字号拉到 **120px** 不溢出（正文 `clamp` + 换行不横向滚动；**板书不缩字**，装不下就**竖向滚动**——`overflow-y:auto` + `scrollbar-gutter:stable`、滚动条常驻不隐藏，V2.1.38）；`CodeEntry` 支持数字键盘（`inputmode="numeric"`）、粘贴整串、回车确认。

**单屏模式 `#/screen`（V2.1）**：迷你控制条 3s 无操作淡出至 12%，鼠标移至底边 80px 或按 `Esc` 唤回；控件 ≥44×44px；`Tab` 顺序限定在控制条内；切场景用 `1–4`。**注意：复制模式下学生看得见控制条与黑屏动作**（见 §9.0），本条不承诺"学生看不到操作"。
