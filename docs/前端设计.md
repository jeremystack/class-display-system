## 1. 两套界面，两个入口

| 端 | 使用者 | 设备形态 | 入口 | 职责 |
|----|--------|----------|------|------|
| **控制台端 console** | 教师 | 手机 / 平板 / 桌面浏览器 | `/index.html`（`/#/login` 起） | 选歌、导航经文、发起投屏、绑定设备；**被动显示**设备状态 |
| **显示端 display** | 无人操作（教室大屏） | 1080p 大屏 / 受控终端浏览器 | `/display.html`（`/#/pair` 起） | 被动接收指令，渲染画面与播放音频 |

**两条硬性架构决策（后续所有设计基于它们）：**

- **D-A：音频在显示端播放。** 教室扩声接在显示端设备上，`<audio>` 元素只存在于 display。控制台**不**加载音频、**不**做解码，只发指令。
  → 推论：控制台的进度条数据来自显示端 `state.report`（5s 一次）＋本地插值平滑；拖动时本地预览、松手才 `seek`。
- **D-B：控制台不做乐观状态猜测。** 任何控制指令都要等 `ack` 或 `state.report` 才更新权威状态；`ack` 超时 3s 才提示（详见 §10）。

> 两套界面共用组件与类型（`src/shared`），但**分别打包**（Vite 多入口），控制台不把 pdf.js、歌词解析等显示端依赖打进去。

## 2. 技术栈（锁死，不得引入其他框架）

| 层 | 选型 | 说明 |
|----|------|------|
| 框架 | **Preact 10 + TypeScript 5（strict）** | 禁止 React/Vue/Svelte 生态；禁止 antd/MUI 等 React 组件库 |
| 样式 | **Tailwind CSS 3** | 只用 utility + `@layer components` 抽 3~5 个复合类；不引 UI kit |
| 状态 | `@preact/signals`（Preact 官方） | 不引 redux/zustand/mobx |
| 路由 | `preact-router`（约 2KB）或手写 hash 路由 | 二选一，全项目统一 |
| 实时通信 | `mqtt`（mqtt.js）over **WSS** | 仅创建一条连接，单例 |
| HTTP | 原生 `fetch` 薄封装（`api.ts`） | 统一注入 JWT、统一错误码转换 |
| 构建 | Vite，双入口 `index.html` / `display.html` | display 产物目标 < 150KB gzip |

**允许的两个例外依赖**：`pdfjs-dist`（仅 display，动态 `import()`，投屏 PDF 时才加载）、`mqtt`。（如开发认为需要第三个，先回帖说明理由。）

|------|------|------|
| `/#/pair` | 配对页 | 显示 6 位设备码 + 二维码（内容为 `?code=XXXXXX`）；含"开始使用"按钮（**必须**，用于解锁浏览器音频自动播放策略，见 §10.6） |

### 5.2 字号与间距

- 控制台：正文 `text-sm`(14) / 标题 `text-xl`(20) / 主控台模块标题 `text-2xl`(24)
- 显示端：基准 1rem = 18px（`html{font-size:18px}`）；歌词 32/40，经文 28/36，投屏正文 40 起
- `fontScale`（0.8~2.0）只作用于 display 的 `.content` 根，**不改** UI chrome（状态条、mini 播放条），避免布局崩
- 间距：4 的倍数；卡片内 `p-4`，模块间 `gap-4`
- 断点：`lg:1024` 为控制台两栏分界；`md:768` 以下为移动单列
- 显示端安全区：内容四周 ≥5%（1920×1080 下 ≈96px），任何字不得贴边

### 6.4 三个必须讲清楚的组件行为

**① `ProgressSlider`（控制台）**
1. 未拖动时：显示 `playerReconciledPosition`（见 §8.3 插值算法），300ms 刷新一次。
2. `pointerdown` → 进入本地预览态，**暂停接收** `state.report` 对进度的覆盖；立即显示手指位置时间。
3. `pointerup` → `POST /control/seek { positionMs }`，进入"确认中"（滑块右上角小 spinner）。
4. 若 3s 内收到 `ack ok` 或 `state.report` 的 `positionMs` 与目标差值 <1500ms → 退出确认中；否则 toast「跳转未确认，已显示实际进度」并回落到上报值。

**② `VerseReader`（`article.navigate` 幂等）**
- 收到 `article.navigate`：先比较 `(volumeId, chapterSn)`；不同则拉 `GET .../chapters/{sn}` 重渲染。
- `anchorVerseSn` 为空 → 定位到章首（`scrollTop=0`）。
- 相同章内 `anchorVerseSn` 相同、且该节已在视口内 → **不滚动**（防重复下发漂移）；不在视口内 → `scrollIntoView({block:'center', behavior:'smooth'})`。
- `displayMode='page'` 时禁用连续滚动，按 `anchorVerseSn` 分屏，一屏 N 节（N 由容器高度算出，`ResizeObserver`）。

**③ `CastLayer`（`fullScreen` 语义）**
- `fullScreen=true`：不透明铺满，隐藏 L1 的所有视觉（**音频继续**）。
- `fullScreen=false`：占据舞台右侧 2/3，左侧保留音乐信息窄栏（配乐 + 板书场景）。
- `cast.end` → 收起本层，**还原**进入前 L1 的视图与滚动位置（不重新拉接口）。

## 7. 状态机

所有状态机都放在各自 store；组件只读信号、发命令。每条转移必须写明"副作用"（调哪个 API / 发哪个 MQTT）与"幂等/超时"。

### 7.1 连接状态机 `connectionStore`（两端共用）

| 状态 | 进入条件 | UI | 副作用 |
|------|----------|-----|--------|
| `idle` | 初始 | 无徽标 | — |
| `connecting` | `mqtt.connect()` 调用后 | 灰点 + "连接中" | 8s 超时 → `offline` |
| `online` | `connack` 成功 | 绿点 | 订阅 `state`，开始 ack 等待表 |
| `degraded` | 连接断开，但自动重连中（≤3 次） | 黄点 + "轮询中" | 控制台启用 `/devices/{id}/state` 2s 轮询；指令仍走 REST（响应里 `delivered:"polling"`） |
| `offline` | 重连 3 次失败 | 红点 + "离线" | 停止轮询改为 5s；禁止播放控制按钮（可点但提示） |

### 7.2 设备会话 `deviceStore`（控制台）

`unbound → binding → bound(online|offline) → occupied(4091)`

| 事件 | 动作 | 结果 |
|------|------|------|
| 提交 6 位码 | `POST /devices/binding` | 200 → `bound`，跳主控台 |
| 设备码过期 | — | 4092 → 自动刷新新码，提示"码已过期，请用新码" |
| 设备被他人控制 | — | 4091 → `occupied`：展示控制者昵称，**不提供强制接管**（单控模式），只能联系对方解绑 |
| 心跳丢失 | `state.report` 30s 未更新 | 卡片置"离线"但保留上一状态快照（灰化） |

### 7.3 音乐播放器 `playerStore`（显示端权威，控制台镜像）

```
idle ──play──> loading ──canplay──> playing ──pause──> paused ──resume──> playing
  ▲               │                    │                 │
  └──stop─────────┴──error────────────┴──(ended)─────────┴──> idle/ended
```

| 转移 | 触发 | 显示端副作用 | 控制台表现 |
|------|------|--------------|-----------|
| `→ loading` | `player.play` | `audio.src=audioUrl; audio.load()`; 显示 spinner + 封面 | 标题秒变（乐观），进度条禁用，直到 `state.report` |
| `→ playing` | `audio.play()` resolve | 起歌词定时器（`timeupdate`，rAF 节流 100ms） | 播放键变暂停 |
| `→ paused` | `player.pause` | `audio.pause()`，记录 `positionMs` | 显示已暂停位置 |
| `→ error` | 音频 4xx/解码失败 | `ack{ok:false,code:4001}`，界面提示 + 保持封面 | toast + 「重试」按钮（重发同 `musicId`） |
| `ended` | `audio.ended` | 自动下一首（若播放列表非空），否则回 `idle` | 列表高亮移动 |

**不变量**：`player.*` 是唯一能改 `audio` 的消息族。文章、投屏、设备类消息都不得触碰 `audio`（见 §9 校验清单）。

### 7.4 文章导航 `articleStore`

`idle → volumes → chapters(volumeId) → reading(volumeId, chapterSn) ⇄ searching`

| 转移 | 触发 | 说明 |
|------|------|------|
| `→ chapters` | 点书卷 | `GET .../chapters?pageNum=1&pageSize=100` |
| `→ reading` | 点章 / `article.navigate` | 拉章内容；写 `PUT /articles/position`（节流 2s） |
| `reading ⇄ searching` | 检索开/关 | 关检索回到原位置，不重载 |
| `article.scroll` | 点下一屏 | 仅仅视觉滚动，不改 `chapterSn`（除非越过章末 → 停在末屏并提示"已到章末"） |
| `article.clear` | — | 回 `volumes`，显示端回 `IdleLayer` |

**没有** `autoPlay / speed / volume` 字段；若服务端误下发，前端按 `mqtt.md` 规则忽略并 warn（前端不崩、不报错弹窗）。

### 7.5 投屏 `castStore`

`idle → draft(有内容) → previewing → casting → ending → idle`，任意态 `error` 可回 `draft`。

| 转移 | 触发 | 动作 |
|------|------|------|
| `→ previewing` | 选择内容完成 | 本地渲染预览（PDF 首屏用 pdf.js 缩略） |
| `→ casting` | 点「开始投屏」 | `text` 直接 `POST /cast/start`；`image/pdf` 先 `POST /cast/presign` 取 URL 上传，再 `cast.start`（`contentUrl`） |
| `→ ending` | 点「结束投屏」/ 设备离线 | `POST /cast/end`；离线时提示"设备离线，恢复后自动结束" |
| `error` | `ack` 4004 或 4093 | 重新申请预签名（最多 2 次），仍失败 → toast + 回 `draft` |

**注意**：`castStore` 的任何转移都**不得**调用 `player` 的 pause/volume（D-04）。

## 8. 与 API / MQTT 的对应关系

### 8.1 控制台动作总表

| 用户动作 | REST | MQTT 下行 | 期望回执 | 状态更新来源 |
|----------|------|-----------|----------|--------------|
| 登录 | `POST /auth/login` | — | — | `authStore` |
| 绑定设备 | `POST /devices/binding` | — | — | 响应 |
| 选歌播放 | `POST /control/play` | `player.play` | `ack` | `state.report` |
| 暂停/继续 | `POST /control/{pause,resume}` | `player.*` | `ack` | `state.report` |
| 拖动进度 | `POST /control/seek` | `player.seek` | `ack` | `state.report` |
| 调音量 | `POST /control/volume` | `player.volume` | `ack` | `state.report` |
| 切音轨 | `POST /control/track` | `player.track` | `ack` | `state.report` |
| 打开书卷 | `GET /articles/volumes` | — | — | 响应 |
| 打开章 | `GET /articles/volumes/{id}/chapters?pageNum=` | — | — | 响应 |
| 定位到某节 | `PUT /articles/position` | `article.navigate` | `ack` | `state.report.viewing` |
| 翻一屏 | — | `article.scroll` | `ack` | `state.report.viewing` |
| 停读/清屏 | — | `article.clear` | `ack` | `state.report` |
| 开始投屏 | `POST /cast/start` | `cast.start` | `ack` | `state.report.casting` |
| 结束投屏 | `POST /cast/end` | `cast.end` | `ack` | `state.report.casting` |
| 轮询兜底 | `GET /devices/{id}/state`（2s） | — | — | 响应（字段名同 `state.report.payload`） |
| 设备上下线 | — | `presence`(retain) | — | `deviceStore` |

> 同一动作**必须**同时具备 REST 与 MQTT 两条路径：REST 是权威入口（鉴权、落库、生成 `msgId`），MQTT 是下行通道；前端只调 REST，由服务端扇出 MQTT，响应里的 `delivered` 告诉前端"走了哪条路"。

### 8.2 显示端消费表

| MQTT `type` | 目标组件 | 幂等要求 |
|-------------|----------|----------|
| `player.play` | `MusicLayer` | 同 `musicId` 且 `positionMs` 差 <1000ms → 不重载，只校时 |
| `player.pause/resume/stop/seek/volume/track` | `MusicLayer` | 按 `msgId` 5 分钟内去重 |
| `article.navigate` | `ArticleLayer` | 同章同锚点不重复滚动（§6.4②） |
| `article.scroll` | `ArticleLayer` | 同 `msgId` 去重；`lines` 缺省 3 |
| `article.clear` | `ArticleLayer` | 清空即回 `IdleLayer` |
| `cast.start` | `CastLayer` | 同 `castId` 不重渲染；`contentUrl` 过期应 ack 4004 |
| `cast.end` | `CastLayer` | 未在投屏态收到 → ack `ok:true`（幂等） |
| `device.ping` | `SystemLayer` | 立即 `pong` |
| `device.reload` | 全局 | 先 `ack` 再 `location.reload()`（延迟 200ms） |

### 8.3 进度插值（控制台）

`state.report` 每 5s 一次，直接展示会跳。算法：

```
onReport(pos, isPlaying):
  base = {pos, at: performance.now(), isPlaying}
onFrame():
  shown = isPlaying ? base.pos + (now - base.at) : base.pos
  shown = min(shown, durationMs)          // 不越过结尾
  if |shown - lastUserSeek| < 1500ms → 用 shown（已对齐）
```

- 音频速率误差不校正（显示端 `timeupdate` 为准，上报即真相）。
- 暂停时不插值。
- 拖动中不插值（§6.4①）。

## 9. 投屏与音乐并存（D-04）——图层栈与不变量

### 9.1 显示端图层（从下到上）

```
L3 SystemLayer   离线条 / 重连 / 版本更新     z-50  非阻塞、半透明
L2 CastLayer     投屏内容                    z-30  fullScreen 时不透明铺满
L1 ContentLayer  MusicLayer | ArticleLayer    z-10  同时只有一个可见
L0 IdleLayer     待机（设备名+设备码+时间）    z-0   无内容时
```

- L1 的 `MusicLayer` **始终挂载**（`audio` 不能因视图切换被卸载，否则声音中断）。
  切到 `ArticleLayer` 时 `MusicLayer` 只隐藏视觉（`hidden`），`<audio>` 保持播放，`MiniPlayerBar` 可见。
- L2 `fullScreen=true` 时把 L1 视觉完全遮住——**遮的是视觉，不是音频**。

### 9.2 四条不变量（code review 必查）

1. `cast.start` / `cast.end` 处理器内**不得出现** `audio.pause()`、`audio.volume`、`audio.src` 赋值。
2. 文章视图切换**不得**停止音乐；`article.clear` 也**不得**停音乐。
3. `player.stop` 是唯一会清空音乐视图的动作；`castend` 后再 `stop` 是操作者的独立选择。
4. 结束投屏后 L1 必须**原样恢复**（同视图、同滚动位置、同播放进度），不重新请求数据。

### 9.3 控制台的"并存"表现

| 场景 | 控制台界面 |
|------|-----------|
| 音乐播放中打开投屏面板 | 面板顶部常驻 chip：`♪ 音乐播放中 03:12 / 05:40` + 次级按钮「暂停音乐」 |
| 点「开始投屏」 | **不弹**"是否暂停音乐"确认框；直接投屏，chip 保持 |
| 投屏中切歌 | 允许；投屏层不动 |
| 结束投屏 | 提示"已结束投屏，音乐继续播放"（仅当音乐在播） |
| 投屏中音乐自然结束 | chip 变「♪ 已结束」，不自动循环 |

### 9.4 一个需要开发的确认点（不阻塞开工）

`fullScreen=false`（配乐+板书并存）时左侧音乐窄栏是**显示端**渲染还是**控制台只在预览里体现**？
本文默认：**显示端渲染左侧窄栏**（老师看得到歌词，屏幕右侧是板书）。开发若因版面成本想改为"非全屏时也铺满"，需回帖说明并由我更新本节。

## 10. 异常与降级

### 10.1 指令未确认

`ack` 3s 未回 → 用**同 `msgId`** 重发 1 次（服务端/显示端按 `msgId` 去重）→ 再 3s 仍未回 → toast「指令未确认」+ 把 UI 回落到最近一次 `state.report` 的真实值。

### 10.2 MQTT 不可用

`connectionStore → degraded`：控制台顶部黄条「实时通道断开，正在用轮询同步（可能有 2s 延迟）」，指令照常可点，响应 `delivered:"polling"` 时在按钮旁显示小黄点。

### 10.3 设备离线

控制台主控台所有控制按钮 `disabled` + 悬浮说明「设备离线」。离线期间不改本地状态，恢复后以 `state.report`（retain）全量对齐。

### 10.4 单控冲突（4091）

绑定阶段返回 4091：显示"该设备已被 <用户> 控制"，提供「联系对方解绑」文案，**不提供**强制接管（与 PRD 单控一致）。

### 10.5 投屏 URL 过期（4093 / ack 4004）

自动重新申请预签名 → 重发 `cast.start`（新 `msgId`、同 `castId`）。两次失败后提示"投屏素材加载失败，请重新选择文件"。

### 10.6 浏览器自动播放策略（必须处理）

显示端刷新后 `audio.play()` 会被浏览器拒绝。因此：
- `/#/pair` 页必须有「开始使用」按钮 —— 在**用户手势**内创建/解锁 `AudioContext`，之后 `/#/display` 才允许自动播放。
- 若仍被拒（`NotAllowedError`）：`SystemLayer` 显示大字提示「点击屏幕任意位置启用音频」，一次性手势后恢复；同时 `ack{ok:false,code:4002}` 让控制台知道"设备需现场点击"。
- 现场部署要求（转运维）：显示端浏览器开启 `--autoplay-policy=no-user-gesture-required`，作为兜底。

### 10.7 第三方音乐不可用

列表来自本地 D1（已同步），详情接口失败时用缓存字段降级；`audioUrl` 取不到 → toast「该曲目音频不可用」，不进入 `loading`。

## 11. 性能预算

| 指标 | 目标 | 手段 |
|------|------|------|
| 控制台首屏 | < 2s（4G，<200KB gz） | 路由级 `lazy()`；歌词/PDF 不进首包 |
| 显示端首屏 | < 1.5s（<150KB gz） | 无路由库分支、无图表；`pdfjs` 动态 import |
| 控制响应 | p95 < 500ms | REST 只做落库+扇出，不阻塞等 ack |
| 切歌 | < 2s 出声 | `audio.preload='auto'`，`player.play` 里带 `audioUrl` 免二次请求 |
| 长章渲染 | 200 节 < 300ms | `VirtualList` 阈值 200；否则直出 |
| 歌词 | 60fps | 只渲染当前 ±20 行，`transform` 滚动 |

## 12. 可用性 / 键盘 / 无障碍

**控制台快捷键**（桌面端，输入框聚焦时禁用）：

| 键 | 动作 |
|----|------|
| `Space` | 播放 / 暂停 |
| `←` / `→` | 文章：上一屏 / 下一屏；音乐：-5s / +5s |

**显示端**：无交互元素；字号可被 `fontScale` 放大到 2.0 不溢出（用 `clamp` + 换行，不横向滚动）。
